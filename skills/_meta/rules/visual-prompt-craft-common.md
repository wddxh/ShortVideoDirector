# 视觉 Prompt 创作通用规则（共享）

本文件提供图像与视频共通的视觉表达方法。具体目标状态、信息层次与身份引用帮助专业判断，不规定创作工序或技能调用；资产链接和输出 schema 则是下游消费的真实契约。

**适用前提**：本文件提供精确表达的专业方法，不以过时印象限制创作，也不保证“写得出就能生成”。将预期画面、模型已验证能力和当前接入限制分开；复杂效果先表达清楚，再由 Creator 核实当前模型/操作支持，遇到不确定性说明风险与取舍，不擅自降级或付费试错。

## 单次请求独立成立

每条图像或视频 prompt 的可用上下文只有本次最终请求文本与实际随请求提供的参考图。创作者从剧本、其他卡片、场景和镜头取得设计依据，再把生成所需事实写入当前文本，或显式绑定本次确实提供的参考图；模型可消费性审核也以这个边界判断。项目内存在某卡、审核者读过原剧本或上一任务生成过图片，都不等于本次模型获得了它。

例如“手持那把剑”在本次缺少剑的描述或有效图像绑定时身份悬空。可按已确认设计写成“右手握黑色缠绳剑柄，窄直银灰剑身朝下，黄铜十字护手”，或在支持的引用区声明真实剑资产并随请求提供对应图片，再用该绑定名称描述持有关系。已有绑定可承载可见身份，当前动作、状态与空间关系仍写在本条；未绑定对象用本地可见特征表达，而不是靠“同款”“另一资产中的”补身份。

其他场景/镜头的故事背景、场次总预算与制作说明保留在源材料元数据区。最终 prompt 表达当前生成目标；“承接上一 shot”应落实为当前起始姿态、持有物、朝向与光线。实际提供的 previous sheet 可显式绑定其可见服饰、道具或朝向，当前目标状态仍由当前 prompt 完整给定。审核者用最终文本和实际 refs 检查缺口，剧本仅用于核对意图，不能在心中替模型补齐缺失信息。

**Sheet 的实际请求边界**：转换器现读完整源 shot，再拼接完整 Panel 规划和整板绘制要求；源对白、旁白、声音与时间上下文都已在本次文本中，不能依上段原则再次摘要/过滤。Card 不存源副本，`图像生成提示` 仅管整板格式、阅读顺序、比例、风格与 labels。源 shot 是叙事权威；Panel 选静态 beats，完整声音帮助理解姿态与表情，不自动成为字幕，也不要求逐句配格或因字数加格。正面具体表达用于写好目标状态，不是删掉合法声音上下文的理由。

### 从故事事实选择当前证据

事实正确不等于生成指令成立。先判断观众此刻是否需要知道，再选择已有设计支持的可见或可听证据；其余留在源材料。年份、罗盘方位不默认进入最终 prompt，也不把“东北”擅自换成屏幕右侧。确有叙事需要的锚点由内容负责人选择，不能为了逐条兑现背景而新增字幕、显示屏或道具。

以下是局部表达对照，不是该场景的新设计；具体外观、站位与持有关系仍以实际材料为准：

| 源句 / 不足 | 当前表达方向 |
|---|---|
| `归历六年夜，桥东北岸` | 年份与地理方位留源背景；当前描述写夜间桥岸已有光线、人物相对桥岸的位置，保留实际屏幕方向，不凭空设计年份字幕。 |
| `完整探星舟已装芯` | 可见舟体按绑定设计写当前轮廓；“已装芯”若仅是前情，留源背景。只有本场需要安装状态证据且设计支持时，才写已确认部件的可见位置与状态，不凭空加透明舱、发光或显示器。 |
| `全身无伤` | 写当前可见肤表、服装和姿态的实际状态，例如材料确实支持时写“露出的皮肤平整”；不扩大为全身展示或新增伤情排除清单。 |
| `原册无未来年份` | 写本镜实际可见的册页内容与布局；内容未给定时请负责人选择必要证据，不臆造年份，也不把未来剧情否定句带入画面。 |
| `场2共55秒` | 留在 shot 结构边界外的场景预算；当前镜头只承载自己的时长与视听事件。 |

## 6 条核心原则

### 原则 1 — 写电影摄影指令而非小说叙事

承载视觉信息的描述要落实为可感知的动作、构图、材质、光线或空间关系。精度服务于意图，不为了显得专业给所有属性编造角度与数值；准确术语首次使用宜简释。

| 反例（文学叙事）| 正例（电影摄影指令）|
|---|---|
| `半张脸藏在散落发丝里，眼尾上挑的那一点锋利清清楚楚` | `中近景，四分之三侧脸，黑色长发覆盖左半张脸到颧骨，右眼可见，眼尾自然上扬` |

### 原则 2 — 正面描述画面真正呈现的内容

这是本项目已有失败案例形成的重点经验：生成 prompt 的画面描述始终围绕希望实际呈现的主体、形状、材质、动作与光线来写，不把“不能出现 X／严禁 X／不要 X”当作主要控制手段。反复点名不想要的对象可能反而强化它；出现错误元素后，优先重写目标状态，而不是加长、前置或加重否定清单。这里保留实际经验，不将其解释成所有模型均不理解否定词的普遍机制。

| 反例（negative phrasing）| 正例（positive 具象描述）|
|---|---|
| `严禁正面立体大宝剑浮雕、金柄红刃宝剑图案、可辨汉字或符文字形、红色符文带`（原案例仍出现这些元素，继续强化排除项没有解决问题）| `晶壳主体为实心古玄铁，表面布满发丝级随机短刻痕；壳内金红色光从数道细缝微弱透出，亮度集中在缝口，周围金属保持暗哑` |

**适用技巧**：
- “不要 X／no X／without X／don't show X”改为目标画面本身；不要在正面 prompt 中反复提及想排除的对象。保留原来的控制意图，用表面、轮廓、空间占用或动作终态表达。
- 例如“不要文字”可具体为“连续、平整、仅有细密随机磨痕的金属表面”；“clean surface”本身未必足够精确。
- 服务专用的 negative prompt 字段与正面画面描述是不同接口；当前未接入的字段不能假装可用，也不能把排除清单混入正面描述作为替代。此经验用于具体表达判断，不做否定词扫描式的机械审核。

### 原则 3 — 显式分解复杂效果

对容易混淆的层级、位置、内容、颜色和文字尺度给出具体关系；仅在需要精确对齐时指定数值，不强求每项都填。

| 反例（参数模糊）| 正例（参数具体）|
|---|---|
| `画面下方几个金字："古法异常体·沈"` | `画面下沿叠加金色简体中文字幕："古法异常体·沈"，整行文字宽度占屏宽 70%，正中对齐，字体宋体加粗` |

> **数量取舍**：单一阅读焦点有助于控制字形、位置和观众注意力。字幕与招牌并存时明确主次、位置和必要文字内容；密集街景可将次要招牌作为环境纹理，不必逐字规定。精确文字能否可靠生成取决于当前模型，必要时提出后期方案而非承诺一次完成。

### 原则 4 — 比喻与心理转译为可见画面

视觉信息应有观众能感知的形状、运动、光影或表演证据。比喻可帮助沟通美术意图，但含糊时宜补充具体目标状态，避免模型把比喻误作新增实体；不是通用修辞禁令。音视频中的旁白、内心独白和声音设计都是合法表达，心理信息不必全部改成外显动作。

| 反例（文学比喻 / 心理描写）| 正例（可见画面 / 动作转译）|
|---|---|
| `剑芒沿她剪影向上撕开像她影子长出一双火翼`（“火翼”可能被误作实体）| `金红色火焰光柱从女性剪影背后向上喷出，两侧对称展开，火焰高度为剪影身高 2 倍` |
| `怕自己被那道红光记住`（心理动机）| `群演手腕反向翻转，掌心从向上翻为向下，0.5 秒内完成，掌心覆盖悬浮光屏` |

**判断方法**：比喻若是风格捷径，补充轮廓、尺度或节奏；若是剧情信息，选择表演、画面或已授权的声音承载。例如“害怕被发现”可表现为手停在门把上、屏息，也可保留剧本内心独白。不要为了可见性改写对白或强加夸张表情。

### 原则 5 — 资产引用：按实际输入绑定身份

下表中省略完整外观的前提是对应图片确实随本次请求提供且名称绑定明确。基础 prompt 的文本自包容不要求空 refs；标准卡同实体视图可绑定实际图片，仍写完整目标和关键共享特征。sheet/shot 可复用实际 refs 的可见身份，仍写足当前目标状态。文件路径本身不是模型可见参考图；标准卡声明由 Creator 映射，sheet/shot 由既有转换器处理。

| 场景 | 自包容程度 | 引用机制 | 应该写 | 不要写 |
|---|---|---|---|---|
| 标准角色 / 物品 / 场景 / 建筑 prompt | 文本自包容，可有实际 refs | 可选基本信息「同实体参考」有序 canonical 卡直链，由 Creator 映射图片 | 完整目标外观；同实体整体/局部/视图保持标志物、几何、材质与状态 | 仅写“同款/见另一卡”而缺本地目标；声明未映射真实图片 |
| 衍生资产 prompt（含旧造型变体） | 重述基础视觉 + 状态变化 | `## 基本信息` 中 `基础资产: [{基础名}](...)` + `基础类型: {type}` 字段单向引用，参考图自动 = 基础 .png | **基础视觉特征**（材质/颜色/布局/标志物）+ 状态变化具体描述 | 仅描述变化（image2image 仍需 prompt 重述基础特征以维持稳定）；引用其他 asset |
| 造型变体 prompt | 重述基础外貌 + 造型差异 | `## 基本信息` 中 `基础角色: [{角色名}](...)` 字段单向引用，参考图自动 = 基础角色 .png | **基础外貌特征**（保持与基础角色一致）+ 造型变化的具体描述（如外卖工作服款式 / 颜色 / 配饰）；**已并入衍生资产，旧文件向后兼容；新建建议用衍生资产模板** | 仅描述差异（image2image 仍需 prompt 重述基础特征以维持稳定）；**已并入衍生资产，新建建议用衍生资产模板** |
| storyboard sheet prompt | 完整源 shot + 完整 Panel + 整板要求，以本次 refs 绑定身份 | 源 header 四类链接与 sheet `## 引用资产` 补充链接并集 | 裸名字或已声明的简单显式 links；源根相对、card 目录相对链接共用槽位 | 在 card 复制源 shot 或另写有损剧情摘要；手写 `{图片N}` |
| storyboard shot prose | 引用多 asset，prose 不重抄完整外观 | 「出场人物」/「引用资产」字段链接 + prose 裸名字 | 明确关键动作终态及相关朝向与空间关系，按需强调可见身份特征 | 重抄整卡掩盖动作；手写 `{图片N}` |

**关键 anti-pattern**：
1. **把自包容误作空 refs** — 标准卡仍完整描述目标，但可用同实体实际图维持共享身份；只有卡名/链接而未上传图片不能提供视觉上下文。衍生资产继续使用既有基础引用与状态规则。
2. **造型变体只写差异不写基础特征** — ❌ "外卖工作服" 一句话；✅ 重述基础角色五官/发型/体型 + "外卖工作服款式"
3. **sheet / storyboard 身份引用失配** — 已绑定资产用裸名字、构图和动作表达；未绑定对象补足本地可见特征或合法实际引用。省略外观只适用于实际绑定的身份，不等于所有对象都只写名字。
4. **LLM 手写 `{图片N}` 占位符** — ❌ 自己在 prompt 写 `[{图片1}]` 或 `[张三:{图片1}]`；✅ 用 markdown 链接 `[张三](assets/characters/张三.md)`，让脚本自动转换
5. **衍生资产仅描述状态变化** — ❌ "古宅被烧毁后焦黑" 一句话；✅ 重述古宅基础视觉（土黄夯土墙 / 黑瓦屋顶 / 雕花门窗）+ 状态描述（焦黑炭化 / 屋顶坍塌 / 窗棂熔毁）

### 原则 6 — 方位以当前画面为基准

生成描述中的位置、朝向与运动方向使用观众所见的当前画面坐标，显式写“画面上方／下方／左侧／右侧”。资产图以本图选定视角为准；shot 以当前机位和时刻为准；sheet 的每个 PANEL 以该格内部视频画面为准，不是整板网格里的格子位置。保留前景／后景、靠近镜头／远离镜头等纵深关系，不把空间压成平面。角色解剖左右另写“角色自己的左手／右手”等，不能把画面左侧当成角色左手，或因正面、背面、转身而错误换手。

东、西、南、北等世界方位可留剧本、场景背景或必要叙事上下文，但不能单独充当生成画面的定位指令。作者核对实际参考、同实体锚点与选定机位后，提交的提示只写画面中实际位置、朝向与动作，不附带“东边投影到左侧”等坐标推导。机位关系的判断留在制作诊断中，不盲换“东=右／西=左”。作者在职责内选择机位；依据不足或源材料冲突时查实际 refs，交对应内容负责人澄清，不在下游覆盖上游事实。

换机位、反打、转身或运镜可能改变屏幕投影，按当前视角和动作阶段重述必要关系，不要求所有角度固定同一左右。连续性保留同一实体的门窗邻接、内外连通等拓扑、标志物与实际持有状态，而非把锚点图的屏幕左右永久锁死。

对白引文、地名、招牌或地图上的方向文字不是位置指令，不机械改写。画内地图／罗盘若确有叙事用途，分别写仪器内容与其画面位置；不凭背景方位新增仪器。此原则用于作者表达与语义审核，不给转换器增加方向替换、正则过滤或新 schema；完整 shot、完整 Panel 文本及既有引用转换照常保留。

以下是有明确视角依据的局部对照，右栏不是从方位词自动推导的默认布局：

| 不足 / 误用 | 有依据的表达 |
|---|---|
| `人物站在东边，灯在西侧上方` | `人物站在画面左侧前景，吊灯位于画面右上方后景` |
| `PANEL 04 在整板右下格，所以人物走向右下方` | 格位仅管阅读顺序；若该格是人物走入门内：`PANEL 04 内，人物从画面下方前景走向画面上方后景的门口，远离镜头`。门口位置须与该格机位、源动作相符。 |
| `人物正对镜头，画面左侧的手即他的左手` | 在正面、双臂未交叉且非镜像的既定姿态下：`人物用自己的右手持杯，该手位于画面左侧`；转身后仍是自己的右手持杯，屏幕位置随姿态核对。 |
| `反打仍让窗在画面左侧，才能保持同一房间` | `窗位于画面右侧后景，门位于窗的画面左侧，人物站在门前` |
| 将对白 `去东门` 改成 `去画面右侧的门`，或只写 `罗盘在北边` | 保留对白及“东门”地名；若罗盘确已设计为当前证据：`罗盘位于画面下方中央，指针朝向盘面标注的“北”`。盘面读数不替代仪器的画面位置。 |

## 数据转换与执行接口

下图表示材料如何被现有脚本消费，不表示专家的技能链或自动下一阶段。只有实际依赖约束执行先后；是否生成、恢复或替换由当前材料与授权决定。

图片批次仅含授权目标与当前已审核提示；默认本地并发 5，Creator 按当前 provider 接入限制用 `--concurrency N` 覆盖，不等于账号总配额。无依赖 jobs 可并发，基础/衍生和声明的 previous-sheet 图片须实际就绪，不为无关 sheets 建立串行顺序或分阶段全量轮询。首次失败/pending 停止新启动并排空 active，保留全批实际结果；不得 shell 并行 raw 调用绕过 runner。

```
  → storyboard-to-prompt.sh: sheet PNG 第一、声明资产按序去重 → IMAGES + DURATION + 绑定/解释前缀与完整 shot（仅替换资产链接）
  → tasks.json (prompt + images + duration)
  → video-gen-dreamina.sh
    (multimodal2video, 已登记授权与输入快照，原顺序传递 --image)
  → submit_id → video-check-dreamina.sh 查询/下载 → mp4
```

真实 wrapper flags 和参数以当前接口为准；需要查询执行细节时，可参考 [图像接口说明](../../creator-provider-dreamina/image.md) 与 [视频接口说明](../../creator-provider-dreamina/video.md)，它们不是必经技能或加载指令。生成 wrapper 维护 `.generation.json`（实际设置、状态、成功输出哈希）；导入/历史图片可无 receipt，不为补记录强制重生。receipt 不是独立视觉验收。

**LLM 关键认知**：不手写 `{图片N}` 占位符。sheet/shot 的链接由转换器绑定；标准卡「同实体参考」由 Creator 逐项映射为有序 `job.images`，本条提示说明对应参考与目标关系。runner 只执行实际 images 的依赖与传参，不推断同实体、不解析标准卡声明，也不验证映射完整性。缺声明图不能静默置空或擅自扩目标补图。

视频 shot 的上传集合仅由 header 的 `出场人物`/`引用资产` 声明；prose 如使用资产 Markdown 链接，必须指向已声明路径，转换为同一实际图片槽位，未声明则输出前报错。完整 shot 的 heading、七字段、声音、时长与本地文本均保留，不按白名单重建；转换器不根据裸名字推断资产或过滤语义。

Sheet 另合并 card 补充 refs：源 header 在先、补充在后，路径规范化去重后人物优先、组内稳定，previous 最后。源正文未声明 links 不能靠 sheet 补漏；裸名按全局绑定理解，不用正则逐名替换。生成与审核都用同一解析请求/引用集合；缺声明、卡或图交责任方，不用摘要解除依赖。Parser 不要求 PNG，runner 检查实际依赖；提示审核不要求未来 PNG，视觉审核须看当前图及直接参考。

## 适用边界

- ✅ 图像生成 prompt（character/location/item/building 与 storyboard sheet）
- ✅ 视频生成 prompt（storyboard shot prose）
- ✅ 视觉 review skill 的"prompt 表达"审核维度
- ❌ 不直接适用：narrative 文本（novel / script / outline / arc）
