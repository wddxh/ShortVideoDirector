# director-input-confirm — short mode

## 上下文加载

- 实际配置 `SVD_CONFIG`（未设时 `config.md`）
- 读用户提供的剧本或故事材料；已有 outline / novel 与本次委托有关时可参考，不为单集补建系列规划。

## 表达参考

以下仅帮助提炼用户已有材料，不是补造剧情的授权。相关 intake 不足时不写新的剧名、概要、开头或结局（包括聊天示例），只列必要缺口，并提供让责任角色在明确范围/约束内决定偏好的选项。记录真实委托，不把空字段变成默认答案；受托艺术细节可留待创作。预览材料也先 intake，创作后的批准另行取得。不把费用/余额作为 intake 必答项，按已选模型使用并保留用户明确限制。

单集材料可优先复述具体入口和情感承诺，如“从一次没送出的道歉进入，最后留下释然而非和好”。这样比只贴“温馨/反转”标签更能确认意图；用户已有成熟表达时直接指出保留处，不重新设计开头结尾。

示例用于需要概括故事的委托，不要求穷尽字段。材料已清楚时可只复述采用范围、保留要求及待确认决定，不为了填写结局类型或卖点重写剧本。

作者一次给齐全部相关确认问题/表、明确题界、完整选项/解释、稳定标签与分支。主 AI 内部保留计划，沿作者题界逐题完整呈现当前内容再用原生单题选择器，相关原始答复/条件批量回作者，不逐题往返。仅缺内容/映射、不相容或计划外决定才提前回询，不推断条件或有损改写，不提前展示全表；以下 Markdown 只是解释参考，不替代可用控件。

未指定剧情但基本主题/前提/体验足够时，Director 可发展默认三个完整故事候选（动机、冲突、推进、结局），明确数量优先；不先问谁决定，不以无关技术未定阻塞。已有剧本/方向/委托复用；确认技能本身不替用户改写材料，正式剧本/资产仍待相关选择已知或委托。

### 输出格式

```markdown
## {主题名称}
- **剧名：** {剧名}
- **剧情概要：** {一句话概括完整剧情走向}
- **结局类型：** {反转 / 温馨 / 开放 / 幽默 / ...}
- **卖点分析：** {为什么适合短视频}
```

## 相关性与授权

- **无 arc 提问**
- **无总集数** (单集短视频)
- 涉及制作时复用用户已确认的单集总时长及严格边界；缺失或不清才询问，不按模板默认。
- 存在具体权利疑虑、授权不清或角色规则冲突时，按主指南列出受影响文本与待决问题，交 Director / 用户确认；不默认改编人名、地名、设定，也不把名称本身当侵权证据

## 专属失败模式自查

- 强加与单集委托无关的多集规划字段
- 未报告具体权利疑虑或规则冲突，或擅自改名/重设计；没有现实名称不等于已完成权利核验
- 剧情概要应简洁，但不能为了字数省略影响采用剧本的关键意图或约束
