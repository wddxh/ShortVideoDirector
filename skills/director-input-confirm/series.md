# director-input-confirm — series mode (new-series / continue-series)

## 上下文加载

- 实际配置 `SVD_CONFIG`（未设时 `config.md`）；已知决定直接复用，不重复询问
- 用户提供的剧本或故事材料优先；已有 arc / 全局摘要仅取相关段落。
- 续集核对相关前集 script 的收尾、角色认知和未回收伏笔；novel 存在且涉及人物声音或改编来源时再读。`上下文集数` 是选取参考范围，不是要求读取所有小说。

## 模式判断

- 以委托和实际已有剧集判断新作或续作，不用可选 outline / arc 的存在推断模式。
- 多集创作通常先考虑人物弧与各集推进是否已有足够规划；适用时建议补充，不要求所有系列都生成相同文件。

## 表达参考

以下仅帮助提炼用户已有材料，不是补造剧情的授权。相关 intake 不足时不编开篇钩子、本集转折或节点（包括聊天示例），只问必要缺口，并提供让责任角色在明确范围/约束内决定偏好的选项。记录真实委托，复用已知连续性，不把空字段变成默认答案；受托艺术细节可留待创作。预览材料也先 intake，创作后的批准另行取得。不把费用/余额作为 intake 必答项，按已选模型使用并保留用户明确限制。

续集确认可抓住“上集留下的后果、本集要探索的选择、不能丢失的关系状态”。如上集已恢复信任，本集的矛盾应来自新处境，而非不加说明地把两人重置为陌生人。新系列则可复述值得持续观看的问题或人物处境，不要求提前承诺全部转折。

以下示例适合需要概括新作或续集方向的委托，不是必填表。成熟剧本可只说明采用内容、保留要求及影响制作的缺口；不为卖点、钩子或人物弧另造用户未要求的设计。

作者一次给齐全部相关确认问题/表、明确题界、完整选项/解释、稳定标签与分支。主 AI 内部保留计划，沿作者题界逐题完整呈现当前内容再用原生单题选择器，相关原始答复/条件批量回作者，不逐题往返。仅缺内容/映射、不相容或计划外决定才提前回询，不推断条件或有损改写，不提前展示全表；以下 Markdown 只是解释参考，不替代可用控件。

未指定剧情但基本主题/前提/体验足够时，Director 可发展默认三个完整故事候选（动机、冲突、推进、结局），明确数量优先；不先问谁决定，不以无关技术未定阻塞。已有剧本/方向/委托复用，续集不重开已定方向；正式剧本/资产仍待相关选择已知或委托。

### new-series 输出格式

```markdown
## {主题名称}
- **剧名：** {剧名}
- **核心设定：** {一句话概括世界观和主角定位}
- **开篇钩子：** {第一集的核心冲突/悬念}
- **卖点分析：** {为什么适合短视频}
- **总集数：** {restate 自 config.md 总集数 字段}
```

### continue-series 输出格式

```markdown
## {走向名称}
- **关键转折：** {本集核心冲突或反转}
- **涉及角色：** {主要出场角色}
- **集尾钩子：** {收束方式 — 描述}
- **对整体剧情的影响：** {如何推动后续剧情}
- **总集数进度：** {当前集 / 总集数，restate}
```

## 配置与授权

- **总集数**：复述 config.md 已有值；缺失时列为待确认，不虚构。
- **每集时长目标**：涉及制作预算时复用用户初始确认的系列共同目标与严格边界，不以前集实际时长滚动调整；缺失或冲突只问必要问题。

## 专属失败模式自查

- 漏掉已知总集数或隐瞒关键配置缺口
- continue-series 与当前已确认人物状态、伏笔或适用 arc 目标矛盾
- 具体权利疑虑或角色规则冲突未交回确认，或仅因出现现实名称就判侵权、静默改名；按主指南保留材料并说明待决问题
