## Choice And Integration

Generation intent comes from the actual target-operation request, not an extra image/video permission prompt. Short/series includes needed new images but stops before video; manual generate-video supplies the initial video request for the entry to persist. Keep the intended user model/parameter configuration and exact resolved submission/card settings. Before capture, explicitly delegated NEW fields can be resolved to supported choices within scope without reasking; fixed or persisted incompatibilities still stop affected work. Generation intent alone does not delegate missing parameters or override none.

Front-load foreseeable parameter decisions and operation grants without asking for unknowable artistic detail. Reuse fixed settings and valid delegations at later stages; capability refresh is an internal check, not renewed consent. On a blocker, inspect current config/materials/grants and consult Director/owner judgment first. Escalate only a real conflict or missing authority that cannot be resolved within them, or a user checkpoint. Existing ongoing grants cover their permitted repeated actions, not new scopes; progress and internally resolved choices need no decision packet.

Discovery checks technical support, not affordability. Do not require budget/cost/credit/balance questions or preflights, or choose cheaper settings to save money. Use the selected model/parameters; honor only actual user-supplied financial limits and report real account/provider failures. Missing preferences can be delegated explicitly to Creator with role, scope and constraints recorded, without demanding financial constraints. Do not repeat settled questions or create designs/prompts while relevant intake is inadequate.

Before video preparation writes, consume the read-only `video-task-inputs.mjs profile TASKS` result using actual SVD_CONFIG. In series mode, source=tasks is authoritative inheritance of provider/model/ratio/resolution from all canonical episode tasks, including the current snapshot. Validate capabilities for that tuple; do not choose again per episode or shot. No earlier episode is required if any consistent prepared snapshot exists. Historical missing/conflicting tuples or fixed-config mismatch block new preparation/payment, not retrieval. Provider none blocks new work. Only source=config permits first selection from actual fixed values and explicitly delegated null fields. Short retains episode ratio/resolution only, without model equality. Duration/content/references/grants remain task-specific. Serialize series preparations; episode locks do not provide cross-episode atomicity.

The `## 参数选择授权` JSON retains actual `decision` and `delegated`. Scopes: `images`, `video`; fields: `provider`, `model`, `ratio`, `resolution`. Missing/empty grants or `auto` do not imply autonomy. Conflicting fixed settings need clarification. Task-only choices do not change defaults.

A selected image model must support required text2image/image2image operations for basic/derived assets and actual refs. Validate counts, ratio, resolution and duration without truncating refs, splitting shots or rewriting approved work. Operation-specific choices require authority; creative changes return to Director and owner.

Only Dreamina execution is wired. Image wrappers support one output and ordered image refs; the actual image2image API receives `--images` as comma-separated paths. Video accepts ordered typed PNG/MP4 refs via `--references-json`, plus duration/ratio/resolution/model, and requires at least one MP4. GIF is rejected. Validate media/count/duration combinations against current help. Use supported wrapper arguments; custom dimensions, multiple outputs and other CLI-only flags are outside the integration. See [shot-inputs.md](../_meta/rules/shot-inputs.md).

Prepare changed settings only within authorized scope and obtain current relevant evidence. Paid video work requires the current typed input contract and MP4, not merely provider acceptance of a media format.
