## 适用范围

本文件区分已采用 outline 的输出契约与创作参考。schema、引用身份、授权和确认时长为硬约束；场景组织与节奏方法按意图选择，亦可从结尾回推、按人物选择展开或整理成熟材料。mode 相关字段见 series.md / short.md。配置均指 SVD_CONFIG，未设时为 config.md。

## 公共骨架字段 (所有 mode 必须包含)

每集 outline 至少包含以下两段：

```markdown
## 本集信息传达
- **{信息内容（角色身份、世界观设定、背景知识、剧情伏笔等）}** — {建议传达方式（主角内心独白/角色对话/群演讨论/新闻播报等）}

（无需传达时标注"无"）

## 场景列表

### 场景 1: {场景标题}
- 目标时长: Ns
- **地点 (location asset):** {asset id 或 "本集新增"}  <!-- asset id = 资产名, 见下方 "asset id 规则" -->
- **出场角色 (character assets):** {asset id 列表 或 "本集新增"}  <!-- 同上 -->
- **节奏角色:** {开场 / 铺垫 / 推进 / 高潮 / 收束 / 过渡 之一}
- **动作:** {支撑本场戏剧任务的行为、反应与变化}

### 场景 2: ...
```

mode 专属字段（如集尾钩子、开场策略、arc 节点对应、结局落点等）在公共骨架之上按 mode 文件追加。

时长行使用纯文本 `- 目标时长: Ns`，N 替换为整数秒数；不要加粗字段或在冒号与数字间插入 Markdown 标记，以便 scene-duration.sh 读取实际秒数。

## 通用规则

### 场景中的戏剧变化

行动型场景可从**戏剧目标（人物当场想达成的事）**与阻力落笔，再写尝试怎样改变局面。用**戏剧节拍（一次行动或回应导致策略、认知或情绪变化的小单元）**组织内容，而非按动作数量切场。“请求留下 → 对方递来行李 → 改口说只是来还钥匙”可以发生在同一场，关键是每次回应怎样改变人物策略。

**情感转折（人物或观众对处境的感受发生变化）**宜有具体触发点与反应：从防备到信任可以落在递出一件私人物品，而非只标“温馨”。若场景意在观察日常或营造氛围，可沿注意力、声音、意象与关系细节组织，不必硬造对抗。

信息可借正在发生的行动进入：角色为拿回借条争执时显露债务关系，比停下来讲背景更紧凑。需要解释时可用对白、旁白或字幕，但检查观众此刻需要知道什么，避免关键选择发生后才补不可缺的依据。

### 场景颗粒度
- 按时空、行动目标与表演连续性决定场景边界，不以动作数量切场
- 连续调度可包含多个动作；独立反应或停顿有戏剧作用时可单独成场，不强制合并
- 不在场景层写镜头建议（景别 / 运动 / 时长）——这是 scriptwriter / storyboarder 的职责

### Asset 引用约束
- 每个场景的 `地点` 和 `出场角色` 字段中引用的 asset，必须满足以下之一：
  - 已在 `assets/characters/` 或 `assets/locations/` 中注册
   - 在本集 outline 的 `## 本集新增资产` 段显式列出（仅规划提案，不是最终制作清单）
- 不允许 dangling reference（引用未注册且未声明新增的 asset）
- item asset（道具）/ building asset（建筑）此阶段**在场景字段中不出现**（场景仅写地点 + 出场角色），但 director-outline 阶段已知的新增 items / buildings 应列入「本集新增资产」段供 scriptwriter 复用（具体格式见下方「新增资产规则」段）

### 节奏角色
- 每个场景**有且仅有一个**节奏角色，取值范围：
  - `开场` — 第一场景专用，承担抓住观众注意力的职责
  - `铺垫` — 信息/情绪/伏笔铺设
  - `推进` — 剧情向前推进
  - `高潮` — 戏剧张力顶点
  - `收束` — 情感落点 / 信息收束 / 短场承接
  - `过渡` — 时空切换 / 视角切换 / 桥段
- 节奏角色标注场景主导功能，不规定出现顺序或每类必有。第一场可直接进入冲突（依功能标为推进或高潮等），必要背景可融入行动；无需为补“铺垫”或“收束”标签另加场景。
- 用张力变化、因果推进和情感落点判断节奏；高潮存在时应有充分支撑，开放或片段式表达按确认意图成立，不强制高潮场或闭环。
- 节奏角色互斥：一个场景不能同时挂两个节奏角色

### 信息传达
- 新角色 / 世界观设定 / 关键伏笔在「本集信息传达」中记录呈现意图，包括暂不揭示或有意留白；制作身份与资产引用仍须明确
- 需要向观众传达的信息给出合适载体（独白 / 对话 / 群演 / 旁白 / 新闻 / 视觉符号等）；有意隐瞒可注明不揭示，不强塞姓名或解释台词
- 传达时机尊重角色认知与叙述视角，不能让角色凭空知道他人身份；也不为补齐信息强迫其他角色代说
- 区分观众必须理解的信息与有意留白；视觉推断、独白、旁白、对白均可使用，说明载体而非强制解释台词

## 时长规划原则

时长不够时可优先考虑下列取舍，按实际因果与情绪选择方法，不把优先级当固定步骤。局部修订若需扩大授权范围，先报告并协调，不能为节奏模板重构全文：

1. **分散吸收**：适合重复场景承载少量关键铺垫时，把关键剧情移植到其他合适场景。例：把街头被旧师门嘲讽的情绪压力融入进入百晓楼前的独白或路过反应，保留原功能而非照搬整场。
2. **减少场景**：适合存在非必要整场时；已有 arc 可参考必需/可选标记，无 arc 则依确认意图、因果和伏笔判断。必需事件保留可识别载体，不能为省时静默删除。
3. **谨慎压缩场景时长**：检查表演、对白和动作是否真的能更紧凑。次要场景可从 25s 压到 18s，但不能为数字达标压掉理解因果所需的台词或反应。
4. **单场景不必自足**：场景可以只是跨场景行动的一部分（如"主角推门进屋"和"主角看见尸体"可拆两场），不强求每场含完整因果。
5. **场景关系可理解**：顺叙、回溯、交叉叙事或高潮先行都应在需要理解时给足时空与因果线索，不要求相邻场景互为因果；被分散吸收的情节仍须能在新载体中识别。
6. **必要事件不可丢**：保留已确认的核心事件；使用 arc 时，其本集必需事件须在 outline 中可识别。确需变更先协调。
7. **总时长服从 config**：sum(场景目标时长) 必须落在 config 每集时长目标区间内（scene-duration.sh 兜底校验）。

## 通用失败模式 (spec §6.3 通用)

- **场景颗粒度失衡** — 边界打断连续表演，或混杂无法理解的时空/任务；按具体效果判断，不按动作数拆合
- **asset dangling reference** — 场景出场角色 / 地点未在 assets/ 注册，且未在「本集新增资产」中声明
- **节奏缺少作用** — 场景重复却没有所需信息、因果或情绪推进；标签集中或缺“高潮”仅是诊断线索，不替代对确认意图的判断
- **节奏角色互斥违反** — 单场景同时挂两个节奏角色
- **写镜头建议越权** — 在场景动作中写「全景推开 / 特写脸部」等景别 / 运动指示
- **信息传达遗漏** — 缺少观众理解所需的信息或未记录揭示/隐瞒意图；有意匿名本身不是遗漏，制作身份另按引用契约核对
- **场景缺目标时长字段** — 公共骨架硬字段，缺即 FAIL
- **总时长偏离 config** — scene-duration.sh FAIL（sum 低于 min 或超 max）
- **事件因果失据** — 关键行为或后果缺少必要依据；倒叙、交叉叙事或非相邻因果本身不算失败（review 质性判）
- **时空关系难以辨识** — 缺少理解所需的时间、地点或视角线索，而非仅因采用跳切或高潮先行判失败（review 质性判）
- **arc 必需事件丢失** — arc 节点标记"必需"事件在 outline 中既无对应场景也未被分散吸收（review 质性判）

## 范围边界

本文件**不规定**以下内容（由 mode 文件管理）：
- 集尾意图 / 开场策略（按已确认意图选择悬念、开放或闭合表达；保留必要因果与情感支撑，不普遍强制悬崖式结尾或解答所有问题）
- 与 arc.md 的对接方式（仅 series）
- 新作与续作的具体委托范围，不由固定调用链决定
- 全局 story/outline.md 同步策略
- mode 专属失败模式（钩子无力、续集状态不一致、结局仓促等）

## 新增资产规则

### 定义

"新增资产" = 在本集 outline 中引用，但**未在 `assets/{characters,locations,items,buildings}/` 注册**的角色 / 地点 / 物品 / 建筑。

### asset id 规则

- **asset id = 资产名**，禁止英文化 / kebab-case 转写。
- **asset id 语言** — 见 `${CLAUDE_PLUGIN_ROOT}/skills/_meta/rules/output-language.md`（规约所有产出文本含 asset id 的语言；同一 outline 内不混语言）
- 与 `creator-create-assets/rules.md` 的资产文件名规则一致（资产名为「张三」→ 文件名 `张三.md` → asset id `张三`）。
- **明确禁止 LLM 自发添加英文 prefix / 转写**：
  - ❌ `char-沈昭`、`loc-地下室`、`item-旧怀表`（前缀英文化）
  - ❌ `char-shen-zhao`、`loc-basement`、`shen-zhao`（kebab-case 转写）
  - ❌ `Shen-Zhao` / `shen_zhao`（en 时大小写或连接符不一致）
  - ✅ `沈昭`（zh） / `Shen_Zhao`（en）

### 「本集新增资产」段格式（director-outline 阶段中间产物）

```
## 本集新增资产
- characters: 王五 (assets/characters/王五.md), 赵六 (assets/characters/赵六.md)
- locations: 地下室 (assets/locations/地下室.md)
- items: 旧怀表 (assets/items/旧怀表.md)
- buildings: (无)
```

- 按 asset 类型分组（4 类固定顺序：characters / locations / items / buildings）
- 每条 `<asset id> (assets/<type>/<asset id>.md)`
- 类型无新增写 `(无)`，**不可省略类型行**

### 复用判断（防止重复创建）

- 写入「本集新增资产」前**必须 Glob** `assets/{characters,locations,items,buildings}/*.md` 扫描已注册全集
- 资产名**精确匹配**已注册文件 → 直接复用（不入「本集新增资产」）
- 名字**相近**时读取相关卡确认身份，不能仅凭相似名称合并；身份不明先询问
- 同一资产不同造型 → 按 `creator-create-assets/rules.md` 的变体规则判断是否独立变体文件

### 规划与制作清单的边界

Director 在 outline 中仅维护 `## 本集新增资产` 提案；修订时移除已放弃的想法。Scriptwriter 根据最终场景在 `script.md` 维护 `## 本集资产清单` 及新增/已有两子段，不能把最终清单写回 outline 或直接合并全部提案。

既有 outline 内的历史清单不是制作依据，不在本任务中迁移或替换；缺 script 清单交 Scriptwriter 采用现有剧本并补齐，不重写故事。资产身份与语言规则仍适用于所有引用。
