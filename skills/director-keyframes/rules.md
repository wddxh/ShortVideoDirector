## 输出格式

输出两个产物：

### 产物 1：keyframes.json（使用 Write 创建/覆盖；增量模式用 Edit）

写入 `story/episodes/$ARGUMENTS[0]/keyframes.json`，结构如下：

```json
{
  "episode": "ep01",
  "keyframes": [
    {
      "id": "KF-EP01-001",
      "narrative_purpose": "建立悬念钩子：主角夜雨独立天台收到陌生短信",
      "composition": "雨中天台夜景，<张三>站在画面左侧栏杆前侧脸朝向镜头，右手举着<黑色翻盖手机>贴近耳侧，屏幕亮着冷蓝色光打亮他下巴；远处城市霓虹模糊在雨幕中",
      "scene": "雨中天台",
      "characters": ["张三"],
      "props": ["黑色翻盖手机"],
      "action": "张三低头读手机屏幕，左手插在风衣口袋里",
      "emotion": "警觉与不安",
      "shot_size": "中景",
      "camera_position": "侧面齐胸平视，主体居左",
      "lighting_tone": "冷蓝雨夜，手机屏幕光打亮下巴轮廓",
      "variation_from_prev": null
    }
  ]
}
```

### 产物 2：本集资产清单（使用 Edit 在 outline.md 末尾追加）

写入 `story/episodes/$ARGUMENTS[0]/outline.md` 末尾，**完全沿用现有格式**：

```markdown
## 本集资产清单

### 新增资产

#### 新角色
- **{角色名}：** {外貌/性格简要描述}

#### 角色造型变体
- **{角色名}-{造型名}：** {造型描述}

#### 新物品
- **{物品名}：** {简要描述}

#### 新场景
- **{场景名}：** {环境简要描述}

#### 新建筑
- **{建筑名}：** {简要描述}

### 已有资产（本集出场）
- **{资产名}（{类型}）：** {本集出场简述}
```

每个新增子分类下无新增时标注"无"。已有资产无出场时省略该分类或标注"无"。

## 字段约束（keyframes.json 每张关键帧）

- **id：** 格式 `KF-EP{NN}-{SSS}`，NN 为集号、SSS 为集内 3 位序号（从 001 开始），如 `KF-EP01-001`、`KF-EP01-002`。增量模式下，新增帧必须用全集内未使用过的最大序号 +1，**不得回收已删除帧的 id**。
- **narrative_purpose：** 一句话说明本帧承担的剧情功能（节点性质 + 推进了什么），如"建立悬念钩子"、"反派身份揭露"、"主角接受任务前的犹豫"。
- **composition：** 整张画面的总览描述，必须用 `<资产名>` 角括号包裹**所有**出场的角色/场景/道具/建筑（与 outline 资产清单一致）。下游 creator-keyframe-images 通过扫描 `<>` 标签自动选取参考图。
- **scene：** 单一场景资产名（不带角括号，纯字符串）。
- **characters：** 出场角色资产名数组（不带角括号），与 composition 中的 `<>` 一一对应。
- **props：** 出场道具资产名数组，同上。
- **action：** 本帧静态画面里角色的姿态/动作描述（不写运镜过程；不写"正要…/即将…"等进行时态）。
- **emotion：** 角色情绪基调，2-6 字短语。
- **shot_size：** 必须是 storyboarder 兼容值之一：`特写`、`近景`、`中景`、`全景`、`远景`、`俯拍`、`仰拍`。
- **camera_position：** 机位描述（如"侧面齐胸平视"、"正面俯视"、"主体居右"），不写运镜过程。
- **lighting_tone：** 本帧的光线、色温、色调描述。
- **variation_from_prev：** 自由文本，描述**当前帧相对于上一关键帧（按集内序号）的视觉变化**——构图变化、光线变化、角色姿态/位置/表情变化、道具增减等。第 1 张关键帧（KF-EP{NN}-001）此字段必须为 `null`。

## 数量规则

- 用 Bash 调用 `bash scripts/read-config.sh "每集分镜数"` 读取本集最大分镜数（设为 N）。
- **硬下限：** 关键帧数量必须 `>= N`。
- **软推荐：** 关键帧数量贴近 `1.5 × N`（向上向下取整都可），给 storyboarder 留出"shot 复用关键帧"和"相邻 shot 共享首尾帧"的余地。
- **无上限**：剧情节点多时可超出 1.5×N，但不得为了凑数而拆分原本完整的节点。

## composition 写作规则

1. **资产标签强制** — 每个出现在画面里的角色/场景/道具/建筑都必须用 `<>` 包裹。校验时遍历 composition，每个 `<>` 内的名字必须在 outline 资产清单（新增 + 已有）中找到。
2. **静态快照** — 描述瞬间状态，不描写过程。"<张三>正要拔枪"❌；"<张三>右手已握住枪柄但未出鞘"✅。
3. **只写可见元素** — 画面外、门后、心理活动、抽象状态都不写。"<反派>就在门后偷听"❌；"门缝下露出黑色皮鞋影子"✅。
4. **空间位置具体** — 写明角色/道具在画面中的位置与朝向（左/中/右、前/后景、面向哪侧）。
5. **元素自包容** — 不引用其他关键帧编号（如"延续上一帧的姿态"），每张关键帧的描述必须独立可读。
6. **不写运镜** — 推/拉/摇/移是 storyboarder 的字段，关键帧只写"机位 + 静态画面"。
7. **不出现具体文字与数字** — 招牌、屏幕内容、车牌、门牌、时间显示等具体文字数字不要写进 composition（视频生成 AI 难以稳定渲染文字）。
8. **不写不可感知信息** — 气味、温度、触感、味道不写进 composition。

## variation_from_prev 写作规则

1. **第 1 张关键帧此字段为 null**。
2. **覆盖三类变化**：构图变化（景别/机位/主体位置）、光线变化（光源/色温/明暗）、角色与道具变化（姿态/表情/位置/新出场/消失）。
3. **写绝对状态对比，不写过程描述**。"镜头从中景拉到特写"✅（描述结果）；"镜头缓慢推近"❌（描述过程，是 storyboarder 的事）。
4. **跳跃合理性自检**：写完后回读 variation，问"这个变化中间是否需要补一张铺垫帧"——如果是，立即新增铺垫关键帧而不是接受跳跃。

## 资产引用规则

1. **优先复用** — 写 composition 用到任何资产前，先在 Glob 出的 `assets/**/*.md` 列表中查找；找到就用现有名字，不要换说法（如已有 `张三` 不要写成 `穿夹克的男人`）。
2. **新增资产登记** — 现有资产中找不到的，登记到 outline.md 资产清单的「新增资产」对应类别下，并在 composition 里用规范化名字。
3. **造型变体命名** — 角色更换服装/装备且对剧情有实质影响时，命名为 `{角色名}-{造型名}`（如 `张三-战斗装`）。无剧情影响则直接用基础资产，不创建变体。
4. **资产清单聚合** — 所有关键帧写完后，遍历每张帧的 `scene` / `characters` / `props` 字段，去重后写入 outline.md 末尾的资产清单章节。

## 数量与覆盖度自检（自检失败必须返工，不允许带瑕疵交付）

写完 keyframes.json 后必须逐条自检：

1. **数量校验**：`len(keyframes) >= 每集分镜数`（来自 config）。不满足则返工补帧。
2. **outline 主要事件覆盖**：outline 的「主要事件」每一项都必须有至少 1 张关键帧承载（用 narrative_purpose 字段比对）。
3. **铺垫与演进覆盖**：主要事件之间不能有视觉跳跃——相邻关键帧之间若存在角色位置/状态/场景的不可解释跳跃，必须补铺垫帧。
4. **集尾钩子覆盖**：outline 的「集尾钩子」必须由最后 1-2 张关键帧承载（最后一张关键帧的 narrative_purpose 应明确指向钩子）。
5. **本集信息传达可视化**：outline 的「本集信息传达」中需要视觉承载的信息（如新角色出场、关键道具出现、地点切换）必须有对应关键帧；纯听觉传达（旁白、对白）的信息无需关键帧承载。
6. **资产引用合法**：composition 中所有 `<>` 标签内的名字都必须能在 outline 资产清单（含新增）或 Glob 出的现有 assets 中找到。

## 增量模式工作流

当 `$ARGUMENTS[1] == "incremental"` 时：

1. **读取现有 keyframes.json**，记录最大已用序号 max_id。
2. **解析 `$ARGUMENTS[2]` 变更说明**，识别变更类型：
   - 新增剧情节点 → 新增关键帧（id = max_id + 1, +2, ...）
   - 删除剧情节点 → 删除对应关键帧（id 不回收）
   - 修改剧情节点 → 修改对应关键帧的字段（id 不变）
3. **不要全量重写**——只 Edit 受影响的部分。未变更的关键帧保持原样（id、所有字段都不动）。
4. **更新 variation_from_prev**：被修改/新增/删除的关键帧的**下一张关键帧**的 variation_from_prev 必须重新计算（因为它的"上一帧"变了）。
5. **同步 outline 资产清单**：
   - 新增关键帧引入新资产 → 追加到「新增资产」
   - 删除关键帧导致某资产不再被任何关键帧引用 → 从清单中移除该资产
   - 修改关键帧导致资产引用变化 → 同步调整
6. **重新跑数量与覆盖度自检**（同上一节）。

## 续集特殊规则

- 第 1 张关键帧必须与上一集最后 1 张关键帧在场景/角色状态上自然衔接——读取上一集 keyframes.json 的最后一帧 composition，本集第 1 帧的 composition 应能合理承接。
- 不得跳过上一集结尾暗示的过渡——如上集结尾说"主角动身去某地"，本集第 1 帧应展示"出发途中/刚到达"，而不是直接在目的地内部。
- 续集第 1 张关键帧的 `variation_from_prev` 仍为 `null`（因为它在本集内是第一张），但 narrative_purpose 应说明承接关系。
