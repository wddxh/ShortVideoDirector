## 输出格式

**标准资产（人物）：**

```markdown
# {角色名}

## 基本信息
- 首次出场：EP{XX}
- 类型：{主角|配角}

## 性格特征
{核心性格、行为倾向、说话风格、口头禅（如有）}

## 视觉描述
{自然语言外观描述，详细具体}

## 图像生成提示
{专门给图像模型用的 prompt，从"视觉描述"提炼出可直接喂给图像模型的描述，必须包含：体型、五官、发型、肤色、服装描述}

## 声音特征
{当前年龄的音色（含已有口音/共鸣特征）、常态语速、常态语调；基线不锁定临场表演}

## 出场记录
- EP{XX}: {简要描述}
```

**标准资产（物品/场景/建筑）：**

```markdown
# {资产名}

## 基本信息
- 首次出场：EP{XX}
- 类型：{道具|场景|建筑}

## 视觉描述
{自然语言外观描述，详细具体}

## 图像生成提示
{专门给图像模型用的 prompt，从"视觉描述"提炼出可直接喂给图像模型的描述}

## 出场记录
- EP{XX}: {简要描述}
```

**衍生资产：**

适用于基础资产发生显著视觉变化的场景（如人物受伤/换装、场景被摧毁、武器破损、建筑焚毁等），覆盖 character / location / building / item 四类基础资产。

```markdown
# {基础名}-{状态名}

## 基本信息
- 基础资产：[{基础名}]({基础名}.md)
- 基础类型：{character / location / building / item}
- 首次出场：EP{XX}
- 类型：衍生资产

## 状态描述
{相对基础资产发生的视觉变化描述}

## 图像生成提示
{基础视觉特征复述 + 状态变化描述}

## 出场记录
- EP{XX}: {简要描述}
```

## 同实体参考（可选基本信息）

四类标准卡可在 `## 基本信息` 增加一行；不需要参考时省略，不改其他必填字段：

```markdown
- 同实体参考：[整体资产](assets/buildings/整体资产.md)
```

多个参考在同一行按实际输入顺序写直接 Markdown links，以逗号分隔；路径是项目根相对 canonical `assets/{characters|items|locations|buildings}/{资产名}.md`，不使用 `../`、绝对路径或新实体 ID/registry。声明的是目标生成需要的直接参考，不是全部关联卡目录，也不递归上传参考的参考。

Creator 先判断整体图能否满足局部/内外视角的制作需求；能复用就不重复生成，确需独立视图时保留各自名称、类别与目录。共享标志物、几何布局、材质和当前状态由同一锚点约束，目标提示正面写清可见范围、视角及这些共同特征，不把局部设计成另一建筑。不同视图本身不是状态衍生；显著受伤、破损、焚毁等仍走既有衍生规则。

选择已有合用图或获准先生成的整体/主视图为锚点；同实体引用必须无环，禁止自身引用、互相引用或间接成环。生成时 Creator 将声明逐项映射到真实图片，不能靠链接文字假装上传。缺卡、缺图或前置未就绪时报告 prerequisite blocked，不能删除声明退回空 refs，也不自动增加生成目标。

例如车站全景与平台近景可以保留为两张制作卡，但平台图应实际引用同一车站基准，保持柱列、棚顶、门口与梯口的相对关系；只改变本图需要的观察位置和范围。建筑类别与场景类别不构成独立实体的依据。声明识别与上传清单的对应由 Creator 核对，执行器只按真实输入图片建立依赖；单图各自合卡不等于两图同址一致，审核应作最小必要的直接比较。

## 规则

上述标准/衍生 schema 均允许额外的可选 `## 本地制作参考`，不替代必填字段。严格按 [本地参考契约](../_meta/rules/local-reference.md) 写唯一 fenced JSON 与叙述，images/sources 均非空、有序、唯一且在项目 references/。基础 `图像生成提示` 必须包含实际参考绑定与本地叙述的完整控制意图、占位边界，不能假定 wrapper 自动拼接卡片其他段。源码/PNG 先制成再交 prompt 独立审核，普通未来生成图不作为提示审核前提。

图像位置表达按 [通用视觉原则 6](../_meta/rules/visual-prompt-craft-common.md)：以本图选定视角写“画面”方向及纵深，角色自己的左右另标明。世界方位不直接代替构图；同实体不同视图按实际锚点保持拓扑与标志物，不强求屏幕左右相同。缺依据先查参考或交负责人，不擅自补布局。

`## 图像生成提示` 按共享 visual-prompt-craft-common 的单次请求边界独立表达完整目标。无实际 refs 的 text2image 只有本条文字，角色持有的物件也需本地可见形状、材质和颜色；“手持那把剑”或另卡名称本身无法提供身份。标准卡可通过下述同实体声明绑定真实图片，仍写完整目标与关键身份特征；文本自包容不等于强制空 refs。衍生 image2image 仍绑定基础图并重述基础特征与当前状态。其他场景的来历和出场记录留元数据区。

1. **创建前必须查重** — 检查已有 assets/ 所有子目录，避免重复
2. **适配图像模型** — 根据 config 中指定的图像模型调整提示词格式
3. **图像提示词语言** — 见 `${CLAUDE_PLUGIN_ROOT}/skills/_meta/rules/output-language.md`（规约所有产出文本含 prompt 字段的语言）。
4. **风格一致性** — 新资产的视觉风格要与已有资产保持一致
5. **提示词质量** — 必须详细描写视觉细节（形状、颜色、材质、纹理、光泽等）。人物重点描写面部细节（五官形状、肤色、眼睛颜色、眉形等）和服饰细节（材质、颜色、剪裁、层次）。人物图像提示词必须包含完整的服装描述，不得省略。物品描写材质和表面纹理，场景/建筑描写光线和空间层次。
6. **人物基础资产设计** — 基于性格、身份与世界观，选择最具代表性、便于复用的形象。中性表情与自然姿态有助于辨认五官和体型，但不是唯一正确构图；职业制服可直接成为基础服饰，不强制便装或额外变体。优先让身份标志可辨；头盔、面具或复杂纹样若是必要身份元素，应明确轮廓、位置和材质，而非一律删去。非必要遮挡、文字和细碎图案会增加稳定复现成本，按叙事价值取舍。
7. **衍生资产独立文件** — 适用 character / location / building / item 4 类基础资产；命名格式 `{基础名}-{状态名}.md`，与基础资产同目录存放（如 `assets/locations/古宅-焚毁.md`）；图像提示词应包含基础视觉特征加上状态变化描述。创建前必须对比基础资产，若该衍生与基础形象没有对剧情有明显影响的视觉区分，则拒绝创建，直接使用基础资产。**禁止递归派生**：基础资产字段必须指向非衍生资产（不得 `衍生 → 衍生`）。旧「造型变体」文件向后兼容（不强制迁移）。
8. **文件名与资产名一致** — 资产文件名必须与资产名称完全一致（如资产名为"张三"则文件名为 `张三.md`），不得对资产名称进行翻译或转写。
9. **严格遵循输出格式** — 每个资产文件必须严格按照上述输出格式模板生成，不得缺少任何字段，不得修改字段名称。人物资产必须包含：基本信息、性格特征（含口头禅）、视觉描述、图像生成提示、声音特征（仅 {音色/语速/语调} 三项物理属性，不含口头禅）、出场记录。物品/场景/建筑资产必须包含：基本信息、视觉描述、图像生成提示、出场记录。衍生资产必须包含：基本信息（含基础资产 + 基础类型）、状态描述、图像生成提示、出场记录。旧造型变体文件向后兼容。

## 声音身份与表演基线

保持现有声音特征段，不新增 schema。音色中的共鸣质感、已设定口音等用于辨认同一角色；语速、语调写常态而非全情境禁令。逐句重音、呼吸、节奏、音量与音高变化由当场意图和触发决定，不放进角色卡当永久限制，口头禅仍属性格特征。

例如 `女声常态3-4字/秒，起伏适中` 可保留为基线，并说明“当场重音、呼吸和句尾走向随表达意图变化”；这不要求所有台词夸张，也不新增未确认的音色或口音。青年卡混入 `老年声，音高幅度小` 会让当前镜头获得竞争指令：当前声音段只给青年适用身份，不附老年备选供模型选择。其他年龄确有制作需要时由相应负责人另行明确适用材料，不能凭本例新增年龄资产。

已有卡仅在授权范围内修正；跨年龄描述含混时先报告具体冲突，不让下游悄悄改写声音或把整段复制当作保真。

## 跨 asset 视觉风格一致 (重要)

同类型资产使用统一 section schema，视觉描述宜采用可比较的组织方式：
- 人物交代五官、发型、服装、体型比例和惯常体态，按身份识别价值分配详略，不强制每段同样长。
- 材质写出漫反射、镜面高光、粗糙度或磨损等可见差异；这些分别指散射光泽、清晰反光、表面细糙与使用痕迹，避免只写“高级质感”。
- 场景/建筑通过前中后景、通行尺度、主光方向和明暗层次建立空间；光照应帮助读懂结构，不用气氛词替代布局。
- 保持项目视觉风格基调；若有意混合写实与手绘等语言，需来自委托设定并说明边界，而非无意漂移。

创作时主动保持一致，独立审核仍可指出影响交付的问题；一致性不意味着所有人物共用一张脸。用轮廓、色彩分区、材质和服饰层次建立身份区分，并优先保持剧情需要的识别特征。

生产资产范围以当前 script 清单为准；可选规划仅补充不冲突的细节。已有卡及其首次出场信息可复用，恢复不重复创建卡或本集记录。清单与视觉需求冲突时返回具体建议，不为填满类别创造无关资产。
