## 输出格式

**标准资产（人物）：**

```markdown
# {角色名}

## 基本信息
- 首次出场：EP{XX}
- 类型：{主角|配角}

## 性格特征
{核心性格、行为倾向、说话风格、口头禅（如有）}

## 视觉描述
{自然语言外观描述，详细具体}

## 图像生成提示
{专门给图像模型用的 prompt，从“视觉描述”提炼可直接使用的目标形象；按下文人物七维组织适用细节，完整保留必要身份与服饰，非人角色使用相容的物种结构表达}

## 声音特征
{当前年龄的音色（含已有口音/共鸣特征）、常态语速、常态语调；基线不锁定临场表演}

## 出场记录
- EP{XX}: {简要描述}
```

**标准资产（物品/场景/建筑）：**

```markdown
# {资产名}

## 基本信息
- 首次出场：EP{XX}
- 类型：{道具|场景|建筑}

## 视觉描述
{自然语言外观描述，详细具体}

## 图像生成提示
{专门给图像模型用的 prompt，从"视觉描述"提炼出可直接喂给图像模型的描述}

## 出场记录
- EP{XX}: {简要描述}
```

**衍生资产：**

适用于基础资产发生显著视觉变化的场景（如人物受伤/换装、场景被摧毁、武器破损、建筑焚毁等），覆盖 character / location / building / item 四类基础资产。

```markdown
# {基础名}-{状态名}

## 基本信息
- 基础资产：[{基础名}]({基础名}.md)
- 基础类型：{character / location / building / item}
- 首次出场：EP{XX}
- 类型：衍生资产

## 状态描述
{相对基础资产发生的视觉变化描述}

## 图像生成提示
{基础视觉特征复述 + 状态变化描述}

## 出场记录
- EP{XX}: {简要描述}
```

## 资产参考（可选基本信息）

四类标准卡可在 `## 基本信息` 增加一行；不需要参考时省略，不改其他必填字段：

```markdown
- 资产参考：[钟楼](assets/buildings/钟楼.md)（本室窗外可见的建筑，提供外观与结构）
```

Creator 选择对目标生成有实际作用的直接参考，在同一行按实际输入顺序写 Markdown links，以逗号分隔，并为每项用 prose 说明关系、采用的特征与用途。路径必须指向实际 canonical 卡，使用项目根相对 `assets/{characters|items|locations|buildings}/{资产名}.md`，不使用 `../`、绝对路径或新实体 ID/registry。可跨类别引用同实体视图、画面包含的另一资产（如窗外建筑）、持有/穿戴物，或仅借鉴共同视觉特征的不同实体。声明不是全部关联卡目录，不递归上传参考的参考。

参考资产图提供声明范围内的外观与结构，完整目标 prompt 可指定它在本图的位置、朝向、尺度、遮挡与可见部分，不默认复制参考图构图。文字与现有资产图足以表达时直接使用；只有复杂关系或精度需要超出这些依据时才增加本地 PNG，不因包含另一资产自动建模。仅借鉴材质、配色或形状语言时明确借用维度，保留目标自身身份，不强制两者同一实体。

确属同实体整体/局部/内外视图时，Creator 先判断现图能否复用；确需独立视图才保留各自名称、类别与目录。共同标志物、几何布局、材质和当前状态由明确锚点约束，按正确观察面表达可见范围，不把局部设计成另一建筑或强求屏幕左右相同。不同视图本身不是状态衍生；显著受伤、破损、焚毁等仍走既有「基础资产」衍生规则。

选择已有合用图或获准先生成的资产图作为依据；必需生成依赖必须无环，禁止自引、互引或间接成环，关系事实本身不要求双向生成引用。Creator 将声明逐项映射到真实图片，按声明顺序放在本地 PNG 后缀之前，并在 prompt review 前按选定 provider 语法写好全局与实际使用处的绑定。缺卡、缺图或前置未就绪报告 prerequisite blocked，不能删除声明退回空 refs，也不自动增加生成或 force 目标；批内已授权前置可等待完成。

例如车站全景与平台近景引用同一车站基准，保持必要柱列、棚顶与梯口关系；室内窗景引用钟楼卡，prompt 指定钟楼在窗框后方的朝向、尺度与可见部分；人物引用道具/服饰卡并写明握持/穿戴关系；不同灯具可只共享黄铜材质而保留各自轮廓。这些都是直接资产参考：第一类目标与来源属于同实体；被包含/持有/穿戴的资产保留自身身份，目标整体不因此等同于参考资产；仅共享特征则保留不同身份。声明到实际图片的对应由 Creator 核对，执行器只按真实输入建立依赖；Reviewer 作最小必要直接比较，不把参考图构图或无影响的像素细节当作复刻门禁。

## 规则

设计与修复时区分用户明确要求、叙事/身份必需特征与自选可替换细节，并在现有交接中说明争议约束的来源和作用。允许使用某细节不等于必须复刻。新增精细标记、形状特征或留白安排前，判断它是否实际支撑识别、剧情或后续使用；无实际作用的精度不升级成重生条件。需要修复时先评估必要性，owner 可在授权内简化或重设计并同步卡片及受影响材料，不持续追逐自选细节；涉及其他 owner、scope 或写入路径先通知原委托方并协调。

资产状态与相关场景一致：核对折叠/展开、持有或存放、使用前后变化及所依赖的基础形象；动作造成的状态变化由剧本/分镜表达，不把临时状态固化成无依据的永久身份。可见左右疑点先核对角色自身左右、观察面、身体朝向和实际镜面/翻转依据；无法可靠判断时请求 fresh 独立视觉检查后再决定替换，不把屏幕左右直接当作解剖左右。

上述标准/衍生 schema 均允许额外的可选 `## 本地制作参考`，不替代必填字段。严格按 [本地参考契约](../_meta/rules/local-reference.md) 写唯一 fenced JSON 与叙述，images/sources 均非空、有序、唯一且在项目 references/。基础 `图像生成提示` 必须包含实际参考绑定与本地叙述的完整控制意图、占位边界，不能假定 wrapper 自动拼接卡片其他段。源码/PNG 先制成再交 prompt 独立审核，普通未来生成图不作为提示审核前提。

图像位置表达按 [通用视觉原则 6](../_meta/rules/visual-prompt-craft-common.md)：以本图选定视角写“画面”方向及纵深，角色自己的左右另标明。世界方位不直接代替构图；同实体不同视图按实际锚点保持拓扑与标志物，不强求屏幕左右相同。缺依据先查参考或交负责人，不擅自补布局。

`## 图像生成提示` 按共享 visual-prompt-craft-common 的单次请求边界独立表达完整目标。无实际 refs 的 text2image 只有本条文字，角色持有的物件也需本地可见形状、材质和颜色；“手持那把剑”或另卡名称本身无法提供身份。标准卡可通过上述「资产参考」声明绑定真实图片，仍写完整目标、关键身份特征及当前关系/用途；文本自包容不等于强制空 refs。衍生 image2image 仍绑定基础图并重述基础特征与当前状态。其他场景的来历和出场记录留元数据区。

1. **创建前必须查重** — 检查已有 assets/ 所有子目录，避免重复
2. **适配图像模型** — 根据 config 中指定的图像模型调整提示词格式
3. **图像提示词语言** — 见 `${CLAUDE_PLUGIN_ROOT}/skills/_meta/rules/output-language.md`（规约所有产出文本含 prompt 字段的语言）。
4. **风格一致性** — 新资产的视觉风格要与已有资产保持一致
5. **提示词质量** — 用具体的形状、颜色、材质、纹理与光泽表达目标。人物按下文七维选择适用细节，完整描述设定中的服装，保留必要身份与服饰差异；无服饰的非人设计按自身结构表达。物品描写材质和表面纹理，场景/建筑描写光线和空间层次。
6. **人物基础资产设计** — 基于性格、身份与世界观，选择最具代表性、便于复用的形象。中性表情与自然姿态有助于辨认五官和体型，但不是唯一正确构图；职业制服可直接成为基础服饰，不强制便装或额外变体。优先让身份标志可辨；头盔、面具或复杂纹样若是必要身份元素，应明确轮廓、位置和材质，而非一律删去。非必要遮挡、文字和细碎图案会增加稳定复现成本，按叙事价值取舍。
7. **衍生资产独立文件** — 适用 character / location / building / item 4 类基础资产；命名格式 `{基础名}-{状态名}.md`，与基础资产同目录存放（如 `assets/locations/古宅-焚毁.md`）；图像提示词应包含基础视觉特征加上状态变化描述。创建前必须对比基础资产，若该衍生与基础形象没有对剧情有明显影响的视觉区分，则拒绝创建，直接使用基础资产。**禁止递归派生**：基础资产字段必须指向非衍生资产（不得 `衍生 → 衍生`）。旧「造型变体」文件向后兼容（不强制迁移）。
8. **文件名与资产名一致** — 资产文件名必须与资产名称完全一致（如资产名为"张三"则文件名为 `张三.md`），不得对资产名称进行翻译或转写。
9. **严格遵循输出格式** — 每个资产文件必须严格按照上述输出格式模板生成，不得缺少任何字段，不得修改字段名称。人物资产必须包含：基本信息、性格特征（含口头禅）、视觉描述、图像生成提示、声音特征（仅 {音色/语速/语调} 三项物理属性，不含口头禅）、出场记录。物品/场景/建筑资产必须包含：基本信息、视觉描述、图像生成提示、出场记录。衍生资产必须包含：基本信息（含基础资产 + 基础类型）、状态描述、图像生成提示、出场记录。旧造型变体文件向后兼容。

## 人物提示的七维表达

参考[官方提示指南（人物 2）](https://bytedance.larkoffice.com/wiki/RXh5ww6EqighMdkVTMccm2d4n7e)，用以下七个维度组织目标人物，而非只堆叠“美丽”“帅气”等评价词：

1. **年龄 / 种族**：明确设定中的年龄或年龄感、种族背景；按已知身份表达，不从情绪或职业推定种族。
2. **肤色 / 皮肤质感**：描述目标肤色与可见表面质感。真人可按目标保留毛孔、雀斑、胡茬、细纹等；美型不等于所有人物统一光滑皮肤。
3. **面部细节**：用脸部轮廓、眉眼、鼻唇等相互配合的特征建立形象。官方建议组合 3–4 项面部细节，是帮助具体化的设计建议，不是机械 quota 或每卡必填数量；按身份识别价值取舍。
4. **眼神 / 表达的底层情绪**：写出可见眼神与支撑表达的情绪底色，区分可复用气质和当场表演，不把一次情绪锁成永久表情。
5. **发型 / 发色 / 环境互动**：交代发型、发色及目标画面需要的风、湿度等互动；环境变化依据当前源材料，基础卡不凭空添加临时状态。
6. **服装剪裁 / 颜色 / 材质 / 穿着方式**：完整表达设定服装的轮廓、配色、面料、层次及实际穿法，保留支撑身份和剧情的差异。
7. **体型 / 情绪气质**：结合体型比例、惯常体态与整体情绪气质描述人物观感，与眼神和服饰形成相容形象。

动画人物也可参考这些维度，细节密度与材质语言服从目标风格。机器人或非人角色按物种结构、传感器、外壳、附肢或覆盖物等相容特征表达身份、感知与气质，不强加人类肤色、真人五官或毛孔；七维是设计参考，不是新增卡片字段或每卡逐项填满的门禁。

当同一次实际提交的故事 prompt 已有 camera / action，人物小节可省去重复机位与动作；必要身份与服饰仍完整保留，不能以精简抹去差异。独立资产图请求仍须自包容，不能依赖未随本次请求提供的故事文字。

## 声音身份与表演基线

保持现有声音特征段，不新增 schema。音色中的共鸣质感、已设定口音等用于辨认同一角色；语速、语调写常态而非全情境禁令。逐句重音、呼吸、节奏、音量与音高变化由当场意图和触发决定，不放进角色卡当永久限制，口头禅仍属性格特征。

例如 `女声常态3-4字/秒，起伏适中` 可保留为基线，并说明“当场重音、呼吸和句尾走向随表达意图变化”；这不要求所有台词夸张，也不新增未确认的音色或口音。青年卡混入 `老年声，音高幅度小` 会让当前镜头获得竞争指令：当前声音段只给青年适用身份，不附老年备选供模型选择。其他年龄确有制作需要时由相应负责人另行明确适用材料，不能凭本例新增年龄资产。

已有卡仅在授权范围内修正；跨年龄描述含混时先报告具体冲突，不让下游悄悄改写声音或把整段复制当作保真。

## 跨 asset 视觉风格一致 (重要)

同类型资产使用统一 section schema，视觉描述宜采用可比较的组织方式：
- 人物按七维组织适用的外貌、服饰、体型比例和惯常体态，非人角色采用相容结构；按身份识别价值分配详略，不强制每段同样长。
- 材质写出漫反射、镜面高光、粗糙度或磨损等可见差异；这些分别指散射光泽、清晰反光、表面细糙与使用痕迹，避免只写“高级质感”。
- 场景/建筑通过前中后景、通行尺度、主光方向和明暗层次建立空间；光照应帮助读懂结构，不用气氛词替代布局。
- 保持项目视觉风格基调；若有意混合写实与手绘等语言，需来自委托设定并说明边界，而非无意漂移。

创作时主动保持一致，独立审核仍可指出影响交付的问题；统一艺术风格不意味着所有角色共用一张脸。按既定设计用轮廓、色彩分区、材质和服饰层次保留身份特征；用户明确设计的同源脸或相同面容必须保留，不为追求差异擅自改脸。

生产资产范围以当前 script 清单为准；可选规划仅补充不冲突的细节。已有卡及其首次出场信息可复用，恢复不重复创建卡或本集记录。清单与视觉需求冲突时返回具体建议，不为填满类别创造无关资产。
