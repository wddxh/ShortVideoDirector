## 额外上下文读取

## Phase 3: Short 专属修正点

### 改结局设计
- 字段：「结局设计」
- 结局必须落地具体：观众离场时记住什么画面 / 情感落点
- 结局类型与描述同步改 —— 类型字段与描述里的画面要对得上
- 改了结局后回查铺垫→冲突→高潮→收束分布是否仍平衡

### 改开场策略
- 字段：「开场策略」
- 单集没有"下集承接"，第一秒必须抓住
- 改时确保仍是可拍的具体画面或对白，不要写"用紧张刺激场景吸引观众"这类空话
- 第一场景节奏角色须为"开场"或"铺垫"

### 改主要事件 / 场景列表
- 加事件时立即检查结局描述是否仍有具体画面 / 动作 —— 防止"长剧第一集"陷阱（结局被压缩潦草）
- config 时长目标内还能装下吗？
- 节奏角色互斥规则不破坏

### 改「本集信息传达」
- 改了角色出场后同步检查"姓名怎么传达"
- 每个新角色单独列条

## Phase 5: 输出 (无全局同步)
- 仅 Write 覆写 `story/episodes/{ep}/outline.md`
- 跳过 story/outline.md 同步 (short 无此文件)

## Short 专属失败模式
- 改成"长剧第一集"：加事件后结局被压缩潦草
- 结局类型与描述脱节：改类型忘改描述，或反之
- 开场策略空话化："用紧张刺激场景吸引观众" → 下游不知拍什么
- 遗漏角色姓名传达：改了角色出场但姓名传达方式未更新
- 单集戏剧结构不完整：铺垫缺失直接进入冲突 / 高潮后无收束
