# Series Mode: director-fix-outline 专属指南

## 额外上下文读取
- `story/outline.md` — 项目维护该摘要时读取相关条目；仅授权包含时同步，不强制新建
- `story/arc.md` — 若存在则读 (识别本集在 arc 中的位置 / 职责)
- 必要时读相关前集 script 的场景、角色状态和伏笔；outline / novel 仅作需要的补充依据

## Phase 3: Series 专属修正点

以下按当前问题选择，不要求逐项改写。只处理授权目标及必要一致性，跨集或扩大范围的影响先交 Director 协调。

### 改 arc 节点对应
- 修订涉及主要事件且有适用 arc 时，回查本集节点；没有时核对已确认的系列目标与事实
- 改后核对适用 arc 目标；意见要求改变该目标时先确认授权，记录冲突与影响，不用在 outline 注记代替修改 arc 的授权
- 字段：「在 arc 中的位置」(arc 节点 / 本集主要事件锚点 / 本集对节点的推进)

### 改集尾钩子
- 钩子空泛时，把“下一集会怎样”落到已经成立的利害关系：秘密公开后谁会失去信任、承诺到期时人物必须选什么。修改揭示也回查后续反应与合作关系；本次不含其他集时报告影响，不代改续集。
- 先核对已确认结尾意图：连续剧情需要承接下一集时，保留具体戏剧悬念，不以“下集见”或空泛思考代替；大结局或自闭合单元保留冲突兑现与情感收束，不强加新悬念。
- 需要悬念时问“观众带什么疑问走”；需要闭合时问“人物选择兑现了什么，观众留下什么感受”。
- 字段仍用「集尾钩子」；闭合结尾可注明“不设续集悬念”并描述落点，不因段名重开故事。

### 改开场策略
- ep01 及已有开场策略的续集均可修改，保持前集收尾与本集入口衔接
- 改时确保是可拍的具体画面 / 对白，不是"用紧张刺激场景吸引观众"

### 改「本集信息传达」
- 改了角色出场 / 伏笔后必须回头更新信息传达对应条目
- 新角色 / 关键信息单独列条，区分制作身份与观众认知；有意匿名或延后揭示可明确记录，不要求当场报姓名

## Phase 5: 同步已有 story/outline.md
- 在授权包含摘要同步时更新现有内容，避免重复追加
- 在 story/outline.md 中定位 `## {ep} 摘要`，用 Edit 更新：
  - 主要场景标题列表
   - 本集结尾意图及其悬念或收束落点
- 仅项目已维护且本次授权包含该摘要时同步；否则报告受影响条目，不为局部修改新建全局文件。

## Series 专属失败模式
- 已授权的全局摘要同步遗漏，或范围外摘要影响未报告
- 修正打破 arc 弧线：本集事件改后 arc 节点未推进，但后续集仍假设它推进了
- 结尾修订偏离意图：需要续集悬念时退化为事件概述；大结局/自闭合单元缺少冲突兑现或情感落点，或被强加悬念破坏闭合。没有续集悬念本身不是失败
- 改了角色出场但信息传达清单仍是旧的
- 跨集人物状态不一致：上集已知 Y，本集开头又问 Y
