# Storyboard Sheet Card Rules

## 字面 Schema

每张 card 严格采用以下 section、字段名和顺序。重复 `### PANEL NN` 块，NN 从 01 连续递增；不得增加替代 section。

```markdown
# shotNN Storyboard Sheet

## 基本信息
- 所属集数：epNN
- 对应分镜：shot N
- 时长：Ns
- 类型：分镜板
- Panel 数量：M
- 已解析图像提供方：{provider}
- 已解析图像模型版本：{model}
- 已解析图片比例：{ratio}
- 已解析图片分辨率：{resolution}

## 引用资产
- [资产名](../../characters/资产名.md)

## 连续性参考
无

## Panel 规划

### PANEL 01
- 时间码：0s-2s
- 景别：中景
- 机位：平视，主体正面偏侧约45度
- 摄影机：固定
- 画面：可见主体、位置、朝向、姿态、动作与环境状态
- 连续性：本 panel 的进入状态与离开状态

## 图像生成提示
整板绘制要求：画布与内部视频比例、行列与阅读顺序、风格、短英文 labels。
```

无 previous 时，`## 连续性参考` 的唯一内容为 `无`。有 previous 时只允许：

```markdown
- [shotNN](./shotNN.md)
- 继承元素：服装、持有物、空间朝向
```

## 资产协议

### 已解析设置

四项值由 Creator 依据实际配置与当前 provider 能力解析，花括号只表示模板，落盘须为真实值。共享图像设置约束 sheets；仅获授权的 `分镜板...` 覆盖可改变范围。`参数选择授权` 的 `delegated.sheets` 明确列出的字段才可自主选择，空值、auto 或加载 skill 不授权。不能把执行选择提升为 config 默认值。

当前 `parseSheetCard` 要求四字段在 `## 基本信息` 各出现一次、非空且非 `none`；provider 当前仅接入 `dreamina`，ratio 为正整数 `宽:高`。模型、分辨率及其组合的支持性仍须核实，parser 非空通过不是能力验证。provider none 可诊断/恢复已有工作，不为新生产卡伪造可执行设置。

在项目根运行 `bash "${CLAUDE_PLUGIN_ROOT}/scripts/storyboard-sheet-to-prompt.sh" --json "{card}"`，得到 `{images, prompt, settings: {provider, model, ratio, resolution}, sourcePath}`。默认无 `--json` 仍输出 `IMAGES:...`、`---`、prompt。解析读取实际源 storyboard，不要求当前或参考 PNG 已存在；runner 提交前检查实际图片依赖。解析成功不是视觉验收或完整 Panel 质量检查。设置变化需获准修改基本信息并重新取得当前 prompt 验收；局部 fixer 不越过其 section 边界。

- 引用集合是源 shot header 的 `出场人物`/`引用资产` 四类链接与 card `## 引用资产` 补充链接的并集。无需在 card 重复源声明；无补充可写 `无`，并集至少含一个基础资产。补充资产仍须有当前 script 清单依据。
- Card links 相对 card 目录（如 `../../characters/角色.md`）；源 shot links 相对项目根（如 `assets/characters/角色.md`）。Panel、整板提示和继承声明可用简单显式 link；转换器将同一规范化路径绑定到同一个 slot。源正文链接必须在源 header 声明，不能用 sheet 补充引用替源补漏。
- 裸名字可在全局参考绑定下自然使用，转换器不按名字正则替换或猜测引用。只写 links/裸名字，不手写 `{图片N}`；同名不得绑定不同资产。禁止 URL、锚点、图片 link、嵌套或带 title 的复杂 link。

## 完整请求与职责

Card 不存源 shot 副本，也不新增“完整源分镜”section。转换器每次从 `story/episodes/{ep}/storyboard.md` 读取唯一实际 `### shot N`，按源结构边界保留完整 header、视听描述、对白、旁白、声音和时间上下文；随后拼接完整 `## Panel 规划` 与 `## 图像生成提示`，不是从字段白名单重建或摘要。除换行规范化、外围空行处理和显式链接绑定外，保留源块和两个 section 的正文，包括 Panel 自有细节。

源 shot 是叙事权威；Panel 规划选择与其相容的静态 beats、姿态、构图和时序。`## 图像生成提示` 仅补整板格式、阅读顺序、比例、风格与 labels，不再重述一份有损剧情摘要。完整对白/声音帮助理解表情和姿态，不自动成为画内字幕，也不要求每句话都有对应一格。源信息过密应由负责人评估，不靠增加 Panel 或删减源上下文解决。

## Panel 拆分

每格方向遵循 [通用视觉原则 6](../_meta/rules/visual-prompt-craft-common.md)，明确“画面上／下／左／右”指该 PANEL 内部视频画面，不是整板格位；保留纵深与角色自己的持有手。投影随源 shot 的实际机位、反打与运镜核对，不从世界方位猜左右，也不复制 previous 的屏幕位置来覆盖当前机位；源依据不足交 Storyboarder，局部修卡不越权补写源事实。

Panel 是分镜板中的单格静态关键画面，不是新增视频 shot。先确定动作转折、观众需要看到的证据与镜头终态，再选最有信息量的瞬间；运动用起落状态和构图变化表达，不能靠把多阶段动作塞进一张静态图实现。空间调度指人物、道具和动作在空间中的安排；连续性指相邻画面的动作和状态一致，首次向用户使用术语时简要解释。

Panel 数量随信息需求决定，不设统一格数；同时考虑画布分辨率、人物辨识度和标签可读性，格数更多不等于覆盖更好。所有时间码须从 `0s` 开始、严格升序、首尾相接并完整覆盖 shot 时长，不得重叠或留白。每个 PANEL 至少对应一个可辨识视觉 beat。

storyboard 时间边界、显式 cut、机位/景别/运动变化、关键姿态、动作结果、人物反应、建立空间与结束落点都是候选选格依据，不是每项变化强制加格。比如开门宜选接触门板与门后空间显露的瞬间；缓慢靠近可用少量构图变化表达，避免近重复格。显式剪切两侧若承载不同信息，应分别覆盖，不为少格漏掉关键证据。

每格应清楚表达已绑定主体、可见动作和构图；按当前信息需要补足环境、朝向、神情、持有物、光线及进入/离开状态，不要求每格重复所有空间字段。只把可见瞬间写入静态画面，声音或内心独白完整保留在请求的源 shot 中；按需要选择可见反应，不逐句配格或把声音渲染为字幕或图标。

## 整板协议

- 整板画布采用本卡 `已解析图片比例`，不是固定 16:9；按格数、构图与分辨率选择行列，阅读顺序左→右、上→下，网格对齐并留一致窄 gutter。
- 每个 panel 内部保持项目视频比例，以 letterbox/pillarbox 适配格子，不裁掉关键主体。
- 使用实际配置的视频风格；彩色项目保持调色一致，授权黑白风格则保持明暗组织，不强制上色。同板线条与光线逻辑连贯，每格关键变化清楚。
- 每个 panel 的短英文 label 固定包含 Panel 编号、时间码、景别、机位、运动五项，例如 `P03 · 5.0s · CU · LOW ANGLE · DOLLY IN`；不得添加剧情字幕、对白、说明长句或中文标签。
- 首次解释标签时，CU 是特写，LOW ANGLE 是低机位仰拍，DOLLY IN 是摄影机向主体移动的推轨，区别于改变焦距的变焦。gutter 是格间窄缝；letterbox/pillarbox 是上下/左右留边以保持画面比例。解释写在交付说明，不向 card 添加新 section 或长标签。
- previous 只可引用编号相邻的上一张 sheet，且当前 shot 确有服装、持有物、位置/朝向等连续元素。无连续元素即写 `无`。
- previous 仅提供声明元素的视觉连续性；不得复制前板网格、panel、构图、机位，也不得让前板决定当前 Panel 数量。

布局例：已授权 3:4 整板承载四个 16:9 视频 panel 时，可用两列两行，格内上下留边保持横幅；若主体因此太小，应比较一列四行的可读性与总高度。9:16 画布可更适合纵向排格。由 Creator 根据实际内容取舍，不改内部视频比例迁就网格，也不把示例比例写成默认。

## Markdown 安全子集

仅允许 ATX headings、普通段落、`- ` 无序列表、行内反引号，以及资产/previous 的简单相对 Markdown link。禁止 raw HTML（包括 `script`、`pre`、`style`）、图片、表格、blockquote、fenced code、脚注、自动链接及复杂 link。prompt 不得包含 HTML-like 标签。

## 写前自检

以转换后的完整 prompt、本次 images 和 sourcePath 检查整板是否独立成立，按共享单次请求边界判断，不把最后一个 section 当整个请求。裸名字只承载实际绑定身份；缺失声明、资产卡或图片交责任方解决，不用摘要或外观改写替代依赖。非资产对象可按已有设计补可见特征。previous 的可见属性仅按声明继承，当前 Panel 仍写清姿态与空间目标；PANEL 编号与时间码是有意生成的标签内容。

- metadata 与源 shot 的 ep、整数编号、时长一致，`Panel 数量` 等于 `PANEL NN` 块数；四项已解析设置与授权和 JSON 转换结果一致。
- 时间覆盖完整，关键 beats 无遗漏，邻格没有无意义重复。
- current links 完整真实；previous 合法且继承元素明确。
- 引用顺序交给现有 `storyboard-sheet-to-prompt.sh` 转换器：先源 header 后 sheet 补充，规范化路径去重，人物优先、各组保持首次出现顺序，previous 最后；card 不手写图片槽位或裁减引用。视频转换器另用当前 sheet 在前的协议，两者不可混用。
- 整板提示明说已解析画布比例、行列/阅读顺序、独立的内部视频比例、项目风格与短英文 label；留边保持比例，不裁掉关键主体。previous 继承声明由转换器另加约束，不需在整板提示重述剧情或 Panel。

## 兼容边界

已有 card 若满足当前 schema，旧 `图像生成提示` 中冗余剧情仍会原样进入组合请求；转换器不自动清理、改写或迁移。只在授权目标内评估冗余或冲突并定向修正，不批量改用户项目。当前解析要求唯一、非空的 `## Panel 规划` 和 `## 图像生成提示`、四项设置及实际唯一源 shot；只有旧摘要或缺 Panel 的卡不兼容，不能补虚构 Panel 来过门禁。现有 fixture 已覆盖该契约，不引入迁移引擎。导入/历史 PNG 无 receipt 仍可按当前输入独立审核；已有 job 的纯取回不因当前卡/源变化受阻。
