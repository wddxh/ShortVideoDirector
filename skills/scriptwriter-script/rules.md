## 输出 schema (per spec §3.4)

已采用剧本按以下场景元数据、视觉摘要、场景内容和转场结构输出。结构顺序是交付格式，不限制创作或故事呈现顺序。配置均指实际 SVD_CONFIG（未设时 config.md）。

```markdown
# epNN 剧本

## 场景 N: <名字>
- 节奏角色: <开场/铺垫/冲突/高潮/收束/过渡>
- 目标时长: <N>s  (可选注释: 微调原因，例 "25s (微调: 对白密集，从基准 20s 加到 25s)")
- 地点: <名称> (assets/locations/<名称>.md)
- 时间: <时间描述>
- 氛围: <环境氛围、光线、声音环境>
- 出场角色: <角色1> (assets/characters/<角色1>.md), <角色2> (assets/characters/<角色2>.md)

### 视觉摘要
<视觉关键点：构图焦点、对比元素、符号道具；详略按场景需要，不指定景别/运动/镜头。>

### 场景内容
<写清场景中可见、可听的动作、对白与反应，按需要加入声音事件、内心声或旁白。可用连贯段落或分行组织，不要求文学散文笔法或每类表达齐备；音效可直接写入内容 (如 "远处响起雷声")，无需 [音效] 标签。>

### 转场
<切 / 淡入淡出 / 叠化 / 划像> → 场景 N+1

## 场景 N+1: ...
（同上结构）

## 本集时长校验
- 总目标: <target_min>-<target_max>s  (config 每集时长目标 = "<原始值>")
- 场景分配: [<s1>, <s2>, ..., <sN>]
- 分配 sum: <SUM>s  (落在 [<min>, <max>] 范围内)
```

**注意**：`## 本集时长校验` section **仅 LLM 自检显示用，不是校验数据源**。真正校验由 `scripts/scene-duration.sh` 从每场景"目标时长"字段累加。

## 叙事起点与观众理解

从全篇的观看经验判断需要哪些起始信息：人物是谁、彼此是什么关系、当前处境、想得到什么、成败对他们有什么意义，以及理解当前行动所必需的世界规则。身份可以是可辨的角色位置而非全名，欲望也可以逐渐显露；在观众需要据此理解行动或情绪前给够依据，不要求首场把人物履历和世界观讲完。

分别检查**事件链**与**观众理解链**：前者是实际发生什么、为何引出后果；后者是观众此刻看见/听见什么、据此能理解到哪一步、为什么关注接下来的选择。作者知道的背景和角色心中的理由不能自动算成观众已知。事件顺序完整，仍可能因关系未建立、动机缺失、因果跳步或必要信息太晚而无法成立。

有意谜团让观众知道正在等待什么，并保有跟随当前行动的依据；可先知道人物在隐瞒而暂不知道原因。检查延迟是否服务体验、后续揭示能否重释前文，而非用“悬念”掩盖本应已懂的事实。开放问题不必全部解答，也不以固定页码或中点强制揭秘。

原创开发在已授权方向、保留要求与预算内主动补足缺失的背景、动机、规则或因果支撑，并落实到场景；不把尚未写出的支撑一概视为不可创造。采用或修复已有材料时先查原文与当前事实，在授权内恢复或展开；若必须新增关键往事、改动关系/规则或结局才能成立，说明缺口及影响交 Director 协调，不把新设定伪装为措辞修正。

区分用户明确保留要求、叙事成立必需的事实与自行选择的可替换表达，交接时说明有争议约束的原话/材料位置及作用。允许使用不等于必须使用；自选无配乐不写成用户禁令。当前实现可在授权内重新设计并同步受影响事实，不把每个装饰细节变成下游必须复刻的剧情条件。

## 沉浸感与可感知表达

以观众实际看见、听见并逐步理解的内容组织沉浸感：人物在争取什么，对方的回应怎样改变下一步，哪项证据使观众改变判断。内心独白、自言自语与旁白可展现主观视角、自我辩解、愿望或声画反差；按本场作用选择，不默认增加声音来解释已经清楚的情绪，也不排斥有效的直陈思想。

创作与修订按情境选用 [对白 craft](dialogue-craft.md) 和 [视听 craft](../_meta/rules/audiovisual-craft.md) 的方法：词汇、句法、称呼与比喻来自生活和关系，具体目标和策略可帮助组织交流。信息可在交涉中出现，主题可由选择及后果承载；听者确有了解需要的直接说明、人物基于自身处境的直接论述也可成立，不为传递信息强造谈判。直接请求、风格化台词与沉默都可成立，不套全员俚语、结巴或对称警句。

**重要互动展开具体台词、行动与反应**：不要用“A 告诉 B 这件事”带过关键告白或交锋。写出 A 怎样开口、B 怎样接话或回避，以及这次回应怎样改变两人的行动。关键情绪给出可感知依据，让观众经历它，而不只在剧本文字里读到“他很痛苦”。

小说可以直接叙述内心；剧本中预期观众感受到的情绪，应落到可见动作、具体对白、声音/画外音或字幕等载体。未表达的往事和心理可供作者或表演理解，但不能独自替代成片里的情绪依据。可听见的画外声音同样是有效表达，不等于“画面外抽象概述”。

作者背景与成片证据分开：年份、方位、装置前情若只供制作理解可留元数据；若当前选择依赖它们，就在场景内容中交代观众可见/可听的事实。必要屏幕、纸面或标识信息写清具体内容；仅当准确措辞、数字或否定词决定判断时保留原字，不只写“出现重要提示”。这不是把所有说明改成屏幕：对白、旁白、声音、行动与状态均可承担信息，按场景选择。

线索出现不等于其含义已被理解，也不等于选择已有依据。若关键在于人物从线索得出判断，写出足以连接二者的语境、比较、话语或行动，并让结果与必要反应在剧本中发生；不以“他看懂了”代替证据，也不要求把每次推理说出口。例如“门已锁”只说明状态；若离开是因为已确认同伴安全，还须有材料支持的确认依据，锁门本身不能兼任。

按作用分配详略：**戏剧动作**展开改变认知、关系或局面的关键行为、结果及反应；**必要连续性**交代使行动成立的起始状态、持有/位置与变化；**实现细节**如具体机位、焦距、切法与阅读窗口由 Storyboarder 设计。日常拿放、走路或操作可概括、略去或与对白重叠，除非其中一步承载必要证据、阻力或转折；不把所有步骤等量强调，也不以“留给导演”删去关键成片事实。

区分作者、角色与观众的知情时点，写清先注意哪里、证据何时显露、谁作出反应。有意隐瞒保留可回认的依据。直接写清影响当前表现的肤表、服装和道具状态，保留人物站位与持有关系；必要注意变化可由视线、动作、对白或声音表达。场景细节服务地点生活感、行动阻力、关系或揭示，不是物件库存；具体性来自可感知关系与变化，而非堆叠形容词。声音按需要交代声源、远近、阻隔、主次和底声，沉默说明停了什么、留下什么；必要声桥关系放既有场景内容/转场，不新增字段或指定机位。

### 全篇与转场

按 [转场与片中文字](../_meta/rules/transition-craft.md) 在已有场景内容/转场中写清必要成片文字及时间、地点和揭示事实，区分场内 UI、观众 SUPER/时间地点/章节/全屏卡与内部制作标题。Scriptwriter 拥有准确原词和叙事事实；已确立“一天后”可由分镜选择卡片呈现，新加隔日跳转须按授权修订故事，不能称为纯版式调整。分镜设计窗口/切点，Creator 实现美术和可选本地引导。独立卡时间纳入场景预算，叠字与宿主画面重叠不重复计时；简单卡片和转场图像按作用使用，不设技巧配额。

交给分镜或资产制作前，沿实际依赖核对人物与道具的状态链：物件折叠/展开、谁拥有或持有、放在哪里、是否可用，以及拿走、交付、损坏或离开造成的后果。后场状态须有前场行动或可信省略支撑，不能无因复位、换主或瞬移；只写影响理解的变化，不把日常步骤逐项展开。省略可由前后状态、时间线索或后续回认成立，也不要求每次转场补完整路程。

已知距离、空间尺度、障碍与通行路线时，早期核对行动能否在可用时间内发生。明显不相容就按授权调整路线、时间关系或事件安排，必要时交 Director 协调摄影覆盖；“飞快赶到”“轻松跨过”等措辞不能修复实际几何与因果冲突。未知量如实保留，不为可拍性硬造精确距离或固定动作秒数。

通读整集，核对场与场及已采用幕之间的真实时间、因果、信息与情绪联系：经过多久、行动或信息如何引到这里、前一选择的后果与情绪是否仍在影响人物。写清必要进入/离开状态与可信省略的依据；幕标签不能代替转变。联系可来自非相邻场景；回溯、交叉叙事、跳时和有意反差均可成立，不要求相邻场景互为因果或情绪平滑，也不强制采用幕结构。

生成任务不是剧本段落或小电影，不为后续分组制造停下、摆终姿、停顿后重新行动的循环。动作、倾听和原句可穿过场景边界；剧本保留事件与声音的实际延续、省略或反差关系，具体硬切时刻、视角及动作阶段由 Storyboarder 落实。真实收束、停顿或过渡场按独立戏剧作用选择，不由任务时长上限决定。

“切/淡入淡出”只说明呈现方式，不能独自解释人物为何突然改变态度或如何获得新信息。优先考虑有效的现有场景方案，可用状态变化、一句说明、声音延续或后续回认提供必要依据；授权原创中，有独立戏剧、情绪或节奏作用的过渡/反应场同样可以成立，不因解释技术上能塞入原场就排除。局部修复仍限本次授权范围，新增场景或跨场扩改超出 scope 时交 Director 协调对应 owner 与必要授权；不为每次换场强加路程、等待或解释场。局部问题也回查其前文支撑，避免只在结尾追加说明而损伤全篇节奏。

### 区分声音的内容与呈现

**声音反应也是表演材料**：倒吸气或追赶后的换气、吞回的笑声、哭腔打断句子、突然喊出的话、长叹与迟疑，都可让情绪进入听觉。按人物的身体状态与交流目的选择具体反应，例如一句玩笑被哭腔截断，能同时呈现掩饰与失控；比给每句台词标“激动/悲伤”更可演，不必堆满一套反应。

- **内心独白**是未说出口的思想。希望观众听见时，写明角色内心声/画外音及具体措辞；其他角色不会因此获知这些思想。
- **自言自语**是人物实际出声说给自己听。写出低语、排练、叹息等表演情境；在场人物是否听到取决于声音和距离。
- **画外音**是声音不由当前画面内说话者呈现的方式，可是内心声、旁白，也可是门外人物的呼喊或电话声。说明声源、内容及场内人物能否听到，避免把不同声音混为一谈。

例如，人物捏着未拨出的电话，内心声说“只问一句，不算认输”，随后低声自语“就一句”。这能把自尊与渴望交给声音和动作共同表现；也可用对白、字幕或有依据的沉默完成同一表达。以上是积极的创作建议，不要求证明声音“不可替代”，不设独白数量或固定组合；实际篇幅仍服从确认时长。

对白、内心独白、自言自语都考虑：说给谁听，此刻想要什么或持什么态度，什么触发了表达变化。比如 `温和询问／带期待／认真` 可作意图摘要，重要互动仍需具体原句与回应；措辞未能传清的关键转折，可补必要的重读、语调或节奏依据，不要求逐句标注声学参数。按实际原文选择，不编造回应，不把自语等同耳语，也不让每句都哭、叹或停顿。

卡片音色与口音支持角色身份，常态语速和语调是表演基线；试探与承诺可以有不同表达。采用当前年龄适用的声音身份，卡片冲突交资产负责人。按已确认片段时长，将原文说话、倾听、反应与动作一起估时；保留指定台词和时长限制，无法兼顾时报告取舍。

## 节奏与渐进估时

### 按戏剧节拍组织表演

**戏剧目标（人物此刻要达成的事）**宜落到可行动的对象，例如“让对方签字”而非“表现焦虑”；**利害关系（成功或失败会失去、得到什么）**使签字不是空动作。目标受阻时，人物可换策略、退让或暴露真实请求，不必把每场都写成争吵。

**戏剧节拍（行动或回应使策略、认知、情绪改变的小单元）**可帮助安排对白和反应空间；**潜台词（话语背后未直说的意思）**让台词、动作与内心声相互补充。口头说“不用送”却停在门边，可以表达等待，不必再解释“他想被挽留”。

**情感转折（对处境的感受改变）**从事件对这个人的意义出发，给出相应回应与后果，而非突然换情绪标签。可以通过具体话语、声音、行动或调度让变化可感知；直说、哭喊、日常闲谈与克制都按人物和场景判断，不套眼神/握拳/呼吸模板。这是因果诊断，不增必填 schema；演员和音乐可深化已有转折，不能代补缺失的理解过程。使用现有场景与资产，不为示例加无关制作负担。

1. **逐步形成分配** — 从粗剧情与用户原始预算判断叙事容量：需要让观众认识多少新事实、经历哪些选择与后果，哪些交流或行动必须展开。再形成暂定场景及相对长短，写出完整对白、关键行动/结果/反应后，以实际内容修正场景秒数。可先试写关键场景或采用成熟剧本；这是估时精度随材料增加的过程，不是必经 outline 或固定创作顺序。

   节奏角色描述实际功能，不设初始百分比、均分场景或等长切片。不要先锁死秒数再把必要理解过程压成摘要，也不靠 filler 填满空格；停顿与生活细节按实际作用保留。允许直接冲突开场、开放结尾及不同结构，不要求标签齐备或四段闭环。

2. **创作分配** — 用户原始集目标已确认的 ±10% 可主动用于对白、倾听、揭示与反应，不只是完稿容差。按 [Director 时长责任](../director-orchestrate/SKILL.md#集总时长责任) 协调场景分配，在 canonical script 更新目标及受影响内容，再交 Storyboarder/Creator 同步分镜与必要下游；范围内不逐次求用户许可。原始基准不随本轮合计滚动，精确目标/显式范围优先。有适用场景基线时可在"目标时长"说明原因，直接采用剧本不虚构大纲基线：
   - 例 `25s (微调: 对白密集，从基准 20s 加到 25s)`
   - 例 `18s (微调: 纯动作无对白，从基准 25s 降到 18s)`

3. **硬校验（适用数值边界）** — 从实际配置读取 `bash "${CLAUDE_PLUGIN_ROOT}/scripts/read-config.sh" "每集时长目标" "${SVD_CONFIG:-config.md}"`，结合用户已确认的容差/严格限制换算秒数，实跑 `scene-duration.sh`；明确无上限的设置按下文处理：
   - 用法 1: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/scene-duration.sh" "story/episodes/{ep}/script.md" --target <N>`，仅用于已确认 ±10% 的单值目标
   - 用法 2: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/scene-duration.sh" "story/episodes/{ep}/script.md" --target-min <M> --target-max <X>`，用于显式范围或更严格边界；精确目标 M=X，不额外扩大
   - 通过条件: 场景"目标时长"字段累加 sum 在上述边界内。系列所有集使用初始用户目标，不以前集实际时长作新目标；缺失/不清先交 Director 澄清，不填默认值
   - 退出码 0=PASS, 1=FAIL；FAIL 在授权内调整并复查。局部修改需要扩展其他场景时先协调，未通过不能宣称时长合格，也不能据此擅自重构故事或拉长集目标；内容适配不了交 Director 提方案或询问用户

4. **专家估时与预演回流** — 完整场景后按原句试读/估读，连同倾听、必要读字、行动、结果与反应判断先后和可信重叠；Storyboarder 再按实际调度、取景与切点细化。Creator 的按需低成本预演可暴露阅读、声音或动作占用冲突，反馈相应 owner 更新 canonical 场景/shot 及受影响下游。文本估读、专家估时、预览计时与最终视频实测分别说明，不能把预演或字数工具当作表演成立的证明。

用户明确“不限时长”或“不设上限”也是已作出的决定，不等于缺配置，不补默认上限或 ±10%。仍给场景可信目标秒数与全篇合计，遵守其余明确边界；只有预算未决定或互相冲突才澄清。`scene-duration.sh` 当前只接受数值上下界，此类非数值/单边限制如实说明该校验不适用，并核对实际已声明边界，不造数值范围或伪报 PASS。本文及 short/series、修订和审核中“范围内/必跑/PASS”均指存在适用数值边界的情况。

## 场景级内容密度诊断

可用目标时长与字数辅助发现表达过密或遗漏，但沉默、动作调度和快速对白需要不同文字量；先判断真实可拍性，不把字数当创作门禁。

例如 10s 写了 500 字/英文词，先区分要念出的台词、可瞬间感知的描写与仅供理解的说明，再试读、估动作；30s 只有 50 字/词，检查等待、走位和反应是否具体且有作用。它们是提问示例，不是通过线；中文字符和英文词也不能按同一语速换算，不据此自动补独白或删戏。

例如 20s 场景的工具参考区间是 160-208 字，但不能据此要求沉默场景增加台词。script-budget.sh 将每个 `## 场景 N` 到下一个二级标题之间的内容交给 word-count.sh；它不是对白专用计数器，也不理解视觉摘要、心理或动作的实际表演时长。

**工具阈值（不是创作合格范围）**：
- script-budget.sh 将 actual < duration × 8 或 > duration × 10.4 标为 `warn`，区间内标为 `ok`；缺时长的场景为 `missing:duration`
- 汇总分别提供 `scenes_warn`、`scenes_ok`、`scenes_missing`；status 优先级为 `missing` > `warn` > `ok`，缺依据不混入密度警告计数
- 这只表示计数偏差；短文可支撑长时间沉默与调度，较长文字也可能仅描述瞬时画面
- 发现真实对白过密或行动依据不足时才在授权内修改，不为数字补写独白、删除表演细节或增加场景

**自检方法**：按人物实际措辞、说话节奏、反应时间、动作复杂度与空间调度检查目标秒数是否可信。试读关键交锋，听出书面腔、同质句式和缺少回应的长段；仅文本估读时说明估读依据，不虚称实测。可先梳理动作或比较密度，不规定步骤，也不靠全员加快语速抹掉转折。

**工具诊断**：需要时运行 `bash ${CLAUDE_PLUGIN_ROOT}/scripts/script-budget.sh <ep>`，读取每场与汇总 `status` 及分类计数。退出 0 仅表示诊断返回，包括缺输入，并非创作验收；缺集参数退出 1。`warn` 不自动触发修订；`missing` 表示缺计算依据，缺剧本/场景时可直接返回 `status:missing:script` / `status:missing:scenes` 而无汇总，不能伪报已计算或合格。独立审核由全新 Reviewer 上下文完成。

**与时长校验的关系**：scene-duration.sh 核对用户确认的单集总预算，是硬约束；节奏比例与字数密度是诊断参考，不能替代或放宽总时长，也不能因计数 warn 判创作失败。实际对白配速与反应空间仍须核对，相关时长 gates 不变。

## Asset 复用与新增

- **同实体地点事实**：在场景地点/视觉摘要或相关资产说明中记录已知整体与局部关系，例如“露台属于议事厅建筑的上层外侧”，必要时带双方已有路径。保留地点与建筑各自名称、目录和实际清单用途，不因同实体强制合并或改名。Scriptwriter 负责事实与出镜需求，不替 Creator 设计共享几何/材质、决定另生视图、选择图像锚点或填写卡片「资产参考」；已有图能否复用与必要独立视图由 Creator 判断。
- **优先复用**：在写剧本前必须扫描 `assets/{characters,locations,items,buildings}/` 目录，剧本中引用的角色/地点/物品/建筑若已存在，直接复用既有 asset 路径，**不重复创建**。
- **新增**：仅当剧情真正引入既有 assets/ 中没有的新元素时才作为"本集新增资产"。
- **引用格式**：角色、地点及需要独立视觉身份的道具/建筑，在场景元数据或正文首次使用处写 `<名称> (assets/<type>/<名称>.md)`，新旧资产都带路径。采用剧本缺路径时先识别和补齐，不能把未标路径的真实资产静默漏掉。

## 本集资产清单：Scriptwriter 所有，保存在 script.md

新写、采用或修订剧本都在 `story/episodes/{ep}/script.md` 内维护以下清单。它是制作依据，覆盖实际场景中的视觉资产，不写回 outline；outline 的新增资产仅为提案。

```
## 本集资产清单

### 新增资产
- characters: 王五 (assets/characters/王五.md), 赵六 (assets/characters/赵六.md)
- locations: 地下室 (assets/locations/地下室.md)
- items: 旧怀表 (assets/items/旧怀表.md)
- buildings: (无)

### 已有资产（本集出场）
- characters: 张三 (assets/characters/张三.md), 李四 (assets/characters/李四.md)
- locations: 茶馆 (assets/locations/茶馆.md)
- items: (无)
- buildings: 鼓楼 (assets/buildings/鼓楼.md)
```

### 段格式约束

- 段标题固定 `## 本集资产清单`（不带阶段标注）
- 子段顺序固定: 先「### 新增资产」后「### 已有资产（本集出场）」
- 每子段下 4 类型行齐全顺序固定（characters / locations / items / buildings），无内容写 `(无)`
- 每条 `<asset id> (assets/<type>/<asset id>.md)`，asset id = 资产名；语言依共享规则，保持已有身份，不擅加英文 prefix 或转写（如 zh 用 `沈昭`，en 用 `Shen_Zhao`）。类别与路径目录一致。

### 从场景识别制作元素

1. 逐个读取 `## 场景 N` 到下一二级标题之间的内容，识别真正出镜且需要视觉一致性的角色、地点、道具和建筑。清单自身、拍摄备注与未出镜的提及不算场景使用证据。
2. 核对并补齐场景引用路径，再按路径稳定去重。普通环境细节不必都单建资产；需稳定身份的关键物件不能漏列。有歧义查相关卡或提出问题。
3. 现有 script 清单中仍被使用的条目保留原新增/已有分类；Creator 建卡不会改变该资产在本集的来源分类。冲突分类先核实，不猜。
4. 首次登记的资产用 Glob 核对真实卡文件：存在则已有，否则新增。大纲提案只帮助识别，不能无条件并入；删去已放弃条目，但不删除共享资产文件。
5. 在 script 中更新清单，保存后运行 `node ${CLAUDE_PLUGIN_ROOT}/scripts/episode-assets.mjs story/episodes/{ep}/script.md all` 验证格式。人工逐场核对覆盖，解析器不负责判断出镜。

### 更新边界与采用已有剧本

script 已有清单时仅替换该二级段落及两子段，到下一 `## ` 标题前停止，保留用户拍摄备注等其他内容；缺清单则追加，不能把缺清单当重写剧本的理由。

采用提供的剧本时保留适用的场景、对白、结局与人物意图；只补必要的格式、路径、时长和清单。outline / arc 均可不存在。历史 outline 清单不能替代场景核对，不迁移或回写其最终清单。

### 失败模式

1. 清单格式破损或误写在 outline —— script 清单消费者无法获得制作依据
2. asset id 英文化（违反 director-outline/rules.md「asset id 规则」）—— 与 creator-create-assets 文件名错配
3. 子段重复 / dedupe 不全（同 asset 在新增 + 复用同时出现）
4. 更新清单破坏其他二级段，或从清单自身反向推导“使用”导致已删资产永不退出
5. 建卡后将本集新增改成已有，或无条件保留未采用的大纲提案

## 公共失败模式 (须主动规避)

1. **写镜头建议** — 越权到分镜师领域 (如"全景推进"/"特写脸部"/"低角度仰拍")
2. **把剧本写成简化小说** — 无场景结构、无时长分配、无视觉摘要、无转场字段
3. **节奏分布失衡** — 剧情需要的转折或情绪变化缺少支撑，或重复场景挤掉关键表达；不按固定百分比或缺少高潮标签判失败
4. **场景对白配速不可拍** — 对白量与场景目标时长不匹配，后续切片必撞 speech-rate gate
5. **视觉摘要含具体镜头建议** — 应只描述视觉关键点 (构图、对比、符号道具)，不指定景别/镜头运动
6. **转场字段缺位** — 场景间缺"切/淡入淡出/叠化/划像"等转场指示
7. **清单不全 / 过度引入** — 剧本使用关键新道具却未列入 script 清单，或不必要的角色挤占有限时长使戏剧失焦

## 参考依据与适用范围

- [John August, How to write a scene（2007）](https://johnaugust.com/2007/write-scene)：采用场景所需成果、长短判断、想象现场到完整场景的展开方法；不照搬其严格删场测试或固定步骤，关系、日常与情绪空间也可有价值。
- [Scriptnotes 269, Mystery Vs. Confusion（2016）](https://johnaugust.com/2016/scriptnotes-ep-269-mystery-vs-confusion-transcript)：采用有意疑问与“本应知道却不知道”的区别，以及必要反应须写在页面上的讨论；不把角色秘密必须中点揭示或所有谜团必须解答变成规则。
- [Scriptnotes 357, Exposition（2018）](https://johnaugust.com/2018/scriptnotes-ep-357-this-title-is-an-example-of-exposition-transcript)：必要信息不可因怕说明而遗漏，自然提问与直接讲解可以成立；不强制将说明藏入冲突或视觉化。
- [Scriptnotes 403, How to Write a Movie（2019）](https://johnaugust.com/2019/scriptnotes-ep-403-how-to-write-a-movie-transcript)：采用处境、选择与人物变化生成结构的方法；该讲座主要讨论传统叙事电影，不将其主题/反主题弧、三幕或受难模式普遍化。
- [Scriptnotes 728, Beats to Scenes with Drew Goddard（2026）](https://johnaugust.com/2026/scriptnotes-episode-728-beats-to-scenes-with-drew-goddard)：采用节点仍须展开为具体场景、重要注意对象须写清、场景之间需要联系的讨论；节目也承认试写发现故事的途径，不强制详细大纲、固定开发顺序或页数换秒数。
- [Walter Murch / Art of the Cut（2020）](https://www.provideocoalition.com/aotc-murch-books/)：采用从全片寻找局部问题根因、以对白和行动想象估时并比较差异的方法；其个人剪辑经验不是统一时长比例、必须两次计时或自动删场授权。
- [ScreenSkills: Script supervisor skills](https://www.screenskills.com/skills-checklists/scripted-film-and-tv/script-supervisor-department/script-supervisor-skills/)：参考前期预估 screen time、识别故事/连续性疑问及关注物理和情绪连续性的职业职责；不在 SVD 增设岗位、分解账本或照搬片场工作流。
- [Toon Boom: How to Create an Animatic](https://docs.toonboom.com/help/storyboard-pro-22/storyboard/getting-started/animatic.html)：参考用有时间的画面、声音及预览修正动作与场景节奏；不把软件默认 panel 时长当创作分配，不要求使用该软件或把粗预演当最终表演验收。

以上是创作讨论、职业资料和软件方法的有限借鉴；本项目的起始信息、理解链及 owner 交接是应用性指导，不是引文或“好莱坞通则”，不转成关键词测试、额外 schema 或门禁。

## 通用规则

- **交流有效** — 按整段互动对人物、关系、情绪、生活感或信息理解的价值取舍，不要求每句推进事件。保留有作用的寒暄、确认、重复与普通短答，避免只剩轮流发表的结论
- **人物表达** — 按具体目标、关系与回应选择言语策略，词汇、句法、称呼和比喻保留人物生活经验；声学身份不能替代措辞差异，直接表态也可有力
- **场景可感知** — 观众需要理解的内容有具体可见或可听表达；对白、内心声、旁白和声音事件均可承载思想，不把可拍性等同于只用画面
- **节奏适配** — 严格遵循 config.md `每集时长目标`，重要场景留足铺垫空间，不在有限时长内压缩过多剧情
- **遵循已确认意图** — 有适用大纲时保留故事弧与结局；素材冲突或改编需要改变核心事件时提出方案交 Director 协调，不擅改其他 owner 的文件
- **角色声音一致** — 角色声音特征必须与资产文件中 `## 声音特征` 描述保持一致
- **内心与声音** — 按声音带来的主观视角、判断、反差或揭示选择具体内容与表演，不默认复述情绪；内心声、自语、旁白、画外对话和字幕均可使用，不设“不可替代”门槛
- **注重视听表达** — 让必要的注意、遮挡、显露和反应有可见或可听依据，细节支撑现场经验与当前行动；观众与人物何时知道事实要清楚，不以形容词数量衡量丰富度
- **权利与采用边界** — 现实人名、地名或商标出现本身不证明侵权；不静默改名或重设计合法提供材料。有具体权利疑虑、授权不清或角色级规则与保留要求冲突时，报告文本依据与影响，交 Director / 用户确认后再改受影响内容；不把改名当作合规保证
- **输出语言** — 所有输出内容的语言必须遵循 config.md `语言` 设置
