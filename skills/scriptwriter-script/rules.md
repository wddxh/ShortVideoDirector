## 输出 schema (per spec §3.4)

已采用剧本按以下场景元数据、视觉摘要、场景内容和转场结构输出。结构顺序是交付格式，不限制创作或故事呈现顺序。配置均指实际 SVD_CONFIG（未设时 config.md）。

```markdown
# epNN 剧本

## 场景 N: <名字>
- 节奏角色: <开场/铺垫/冲突/高潮/收束/过渡>
- 目标时长: <N>s  (可选注释: 微调原因，例 "25s (微调: 对白密集，从基准 20s 加到 25s)")
- 地点: <名称> (assets/locations/<名称>.md)
- 时间: <时间描述>
- 氛围: <环境氛围、光线、声音环境>
- 出场角色: <角色1> (assets/characters/<角色1>.md), <角色2> (assets/characters/<角色2>.md)

### 视觉摘要
<视觉关键点：构图焦点、对比元素、符号道具；详略按场景需要，不指定景别/运动/镜头。>

### 场景内容
<prose 风格的连贯叙事：角色动作、对白、内心独白、旁白、声音反应交织。音效融在 prose 里 (如 "远处响起雷声")，无需 [音效] 标签。>

### 转场
<切 / 淡入淡出 / 叠化 / 划像> → 场景 N+1

## 场景 N+1: ...
（同上结构）

## 本集时长校验
- 总目标: <target_min>-<target_max>s  (config 每集时长目标 = "<原始值>")
- 场景分配: [<s1>, <s2>, ..., <sN>]
- 分配 sum: <SUM>s  (落在 [<min>, <max>] 范围内)
```

**注意**：`## 本集时长校验` section **仅 LLM 自检显示用，不是校验数据源**。真正校验由 `scripts/scene-duration.sh` 从每场景"目标时长"字段累加。

## 沉浸感与可感知表达

**推荐在适合的场景多设计主角内心独白与自言自语**，展现想法、感受和判断，增强观众代入感。独处、作出选择、口是心非或强忍情绪时，让人物的自我辩解、犹豫和愿望进入声音与表演，往往比只写情绪标签更有力量。

**重要互动展开具体台词、行动与反应**：不要用“A 告诉 B 这件事”带过关键告白或交锋。写出 A 怎样开口、B 怎样接话或回避，以及这次回应怎样改变两人的行动。关键情绪给出可感知依据，让观众经历它，而不只在剧本文字里读到“他很痛苦”。

小说可以直接叙述内心；剧本中预期观众感受到的情绪，应落到可见动作、具体对白、声音/画外音或字幕等载体。未表达的往事和心理可供作者或表演理解，但不能独自替代成片里的情绪依据。可听见的画外声音同样是有效表达，不等于“画面外抽象概述”。

作者背景与成片证据分开：年份、罗盘方位、装置已安装等事实可留场景元数据或制作背景；只有观众当前需要知道时，才选择已有设计支持的动作、声音或可见状态，不为每个事实新增字幕/显示器。`全身无伤`、`原册无未来年份` 这类连续性排除不替代当前肤表、册页的实际状态。`开始看册而非继续凝望` 应给出目光从原对象移向册页的动作，保留人物站位与持有关系；不替分镜师规定机位。

### 区分声音的内容与呈现

**声音反应也是表演材料**：倒吸气或追赶后的换气、吞回的笑声、哭腔打断句子、突然喊出的话、长叹与迟疑，都可让情绪进入听觉。按人物的身体状态与交流目的选择具体反应，例如一句玩笑被哭腔截断，能同时呈现掩饰与失控；比给每句台词标“激动/悲伤”更可演，不必堆满一套反应。

- **内心独白**是未说出口的思想。希望观众听见时，写明角色内心声/画外音及具体措辞；其他角色不会因此获知这些思想。
- **自言自语**是人物实际出声说给自己听。写出低语、排练、叹息等表演情境；在场人物是否听到取决于声音和距离。
- **画外音**是声音不由当前画面内说话者呈现的方式，可是内心声、旁白，也可是门外人物的呼喊或电话声。说明声源、内容及场内人物能否听到，避免把不同声音混为一谈。

例如，人物捏着未拨出的电话，内心声说“只问一句，不算认输”，随后低声自语“就一句”。这能把自尊与渴望交给声音和动作共同表现；也可用对白、字幕或有依据的沉默完成同一表达。以上是积极的创作建议，不要求证明声音“不可替代”，不设独白数量或固定组合；实际篇幅仍服从确认时长。

对白、内心独白、自言自语都考虑：说给谁听，此刻想要什么或持什么态度，什么触发了表达变化。比如 `温和询问／带期待／认真` 可作意图摘要，但重要互动还要有原句重点的重读、句尾音高走向、呼吸或节奏等可听依据。按实际原文选择，不编造回应，不把自语等同耳语，也不让每句都哭、叹或停顿。

卡片音色与口音支持角色身份，常态3-4字/秒、起伏适中只是基线；告别中的试探与承诺可有不同表达。青年场景不带入老年声备选指导，卡片冲突交资产负责人。采用或修订已有18s片段时，将原文说话、倾听、反应与动作一起估时；不静默延长18s或改写已要求保留的台词，放不下先报告取舍。

## 节奏 → 时长映射

### 按戏剧节拍组织表演

**戏剧目标（人物此刻要达成的事）**宜落到可行动的对象，例如“让对方签字”而非“表现焦虑”；**利害关系（成功或失败会失去、得到什么）**使签字不是空动作。目标受阻时，人物可换策略、退让或暴露真实请求，不必把每场都写成争吵。

**戏剧节拍（行动或回应使策略、认知、情绪改变的小单元）**可帮助安排对白和反应空间；**潜台词（话语背后未直说的意思）**让台词、动作与内心声相互补充。口头说“不用送”却停在门边，可以表达等待，不必再解释“他想被挽留”。

**情感转折（对处境的感受改变）**需要触发与可感知反应，而非突然换情绪标签。空间调度可让关系变化可见：从隔桌问话到坐在同侧，或把挡在两人之间的物件移开。使用现有场景与资产，不为示例加无关制作负担；静观场景也可通过注意力与声音变化组织节拍。

1. **LLM 自由分配** — 节奏角色作为软引导，参考分布：
   - 高潮 ~30%
   - 冲突 ~25%
   - 铺垫 ~20%
   - 开场 / 收束 / 过渡 共 ~25%

   实际分配由 LLM 根据本集剧情张力自由调整，软引导**非硬约束**。节奏角色描述实际功能，不要求每类齐备、固定顺序或四段闭环；允许直接冲突开场。结尾开放或闭合依确认意图，留白需有支撑，不默认漏写。

2. **微调注释** — 有适用基线且偏离时，在"目标时长"字段说明原因；直接采用剧本不虚构大纲基线：
   - 例 `25s (微调: 对白密集，从基准 20s 加到 25s)`
   - 例 `18s (微调: 纯动作无对白，从基准 25s 降到 18s)`

3. **硬校验** — 从实际配置读取 `bash "${CLAUDE_PLUGIN_ROOT}/scripts/read-config.sh" "每集时长目标" "${SVD_CONFIG:-config.md}"`，结合用户已确认的容差/严格限制换算秒数，实跑 `scene-duration.sh`：
   - 用法 1: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/scene-duration.sh" "story/episodes/{ep}/script.md" --target <N>`，仅用于已确认 ±10% 的单值目标
   - 用法 2: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/scene-duration.sh" "story/episodes/{ep}/script.md" --target-min <M> --target-max <X>`，用于显式范围或更严格边界；精确目标 M=X，不额外扩大
   - 通过条件: 场景"目标时长"字段累加 sum 在上述边界内。系列所有集使用初始用户目标，不以前集实际时长作新目标；缺失/不清先交 Director 澄清，不填默认值
   - 退出码 0=PASS, 1=FAIL；FAIL 在授权内调整并复查。局部修改需要扩展其他场景时先协调，未通过不能宣称时长合格，也不能据此擅自重构故事或拉长集目标；内容适配不了交 Director 提方案或询问用户

## 场景级内容密度诊断

可用目标时长与字数辅助发现表达过密或遗漏，但沉默、动作调度和快速对白需要不同文字量；先判断真实可拍性，不把字数当创作门禁。

例如 10s 写了 500 字/英文词，先区分要念出的台词、可瞬间感知的描写与仅供理解的说明，再试读、估动作；30s 只有 50 字/词，检查等待、走位和反应是否具体且有作用。它们是提问示例，不是通过线；中文字符和英文词也不能按同一语速换算，不据此自动补独白或删戏。

例如 20s 场景的工具参考区间是 160-208 字，但不能据此要求沉默场景增加台词。script-budget.sh 将每个 `## 场景 N` 到下一个二级标题之间的内容交给 word-count.sh；它不是对白专用计数器，也不理解视觉摘要、心理或动作的实际表演时长。

**工具阈值（不是创作合格范围）**：
- script-budget.sh 将 actual < duration × 8 或 > duration × 10.4 标为 `fail`，区间内标为 `ok`
- 这只表示计数偏差；短文可支撑长时间沉默与调度，较长文字也可能仅描述瞬时画面
- 发现真实对白过密或行动依据不足时才在授权内修改，不为数字补写独白、删除表演细节或增加场景

**自检方法**：按人物说话速度、反应时间、动作复杂度与空间调度检查目标秒数是否可信。可先试读对白或梳理动作，也可先比较密度，不规定步骤。

**工具诊断**：需要时运行 `bash ${CLAUDE_PLUGIN_ROOT}/scripts/script-budget.sh <ep>`，读取每场与汇总 `status`，退出 0 不表示创作合格。`fail` 不自动触发修订，`missing` 表示缺计算依据，不能伪报结果；独立审核由另一个 Director 上下文完成。

**与时长校验的关系**：scene-duration.sh 核对用户确认的单集总预算，是硬约束；节奏比例与字数密度是诊断参考，不能替代或放宽总时长，也不能因计数 fail 判创作失败。

## Asset 复用与新增

- **同实体地点事实**：在场景地点/视觉摘要或相关资产说明中记录已知整体与局部关系，例如“露台属于议事厅建筑的上层外侧”，必要时带双方已有路径。保留地点与建筑各自名称、目录和实际清单用途，不因同实体强制合并或改名。Scriptwriter 负责事实与出镜需求，不替 Creator 设计共享几何/材质、决定另生视图、选择图像锚点或填写资产卡同实体参考；已有图能否复用与必要独立视图由 Creator 判断。
- **优先复用**：在写剧本前必须扫描 `assets/{characters,locations,items,buildings}/` 目录，剧本中引用的角色/地点/物品/建筑若已存在，直接复用既有 asset 路径，**不重复创建**。
- **新增**：仅当剧情真正引入既有 assets/ 中没有的新元素时才作为"本集新增资产"。
- **引用格式**：角色、地点及需要独立视觉身份的道具/建筑，在场景元数据或正文首次使用处写 `<名称> (assets/<type>/<名称>.md)`，新旧资产都带路径。采用剧本缺路径时先识别和补齐，不能把未标路径的真实资产静默漏掉。

## 本集资产清单：Scriptwriter 所有，保存在 script.md

新写、采用或修订剧本都在 `story/episodes/{ep}/script.md` 内维护以下清单。它是制作依据，覆盖实际场景中的视觉资产，不写回 outline；outline 的新增资产仅为提案。

```
## 本集资产清单

### 新增资产
- characters: 王五 (assets/characters/王五.md), 赵六 (assets/characters/赵六.md)
- locations: 地下室 (assets/locations/地下室.md)
- items: 旧怀表 (assets/items/旧怀表.md)
- buildings: (无)

### 已有资产（本集出场）
- characters: 张三 (assets/characters/张三.md), 李四 (assets/characters/李四.md)
- locations: 茶馆 (assets/locations/茶馆.md)
- items: (无)
- buildings: 鼓楼 (assets/buildings/鼓楼.md)
```

### 段格式约束

- 段标题固定 `## 本集资产清单`（不带阶段标注）
- 子段顺序固定: 先「### 新增资产」后「### 已有资产（本集出场）」
- 每子段下 4 类型行齐全顺序固定（characters / locations / items / buildings），无内容写 `(无)`
- 每条 `<asset id> (assets/<type>/<asset id>.md)`，asset id = 资产名；语言依共享规则，保持已有身份，不擅加英文 prefix 或转写（如 zh 用 `沈昭`，en 用 `Shen_Zhao`）。类别与路径目录一致。

### 从场景识别制作元素

1. 逐个读取 `## 场景 N` 到下一二级标题之间的内容，识别真正出镜且需要视觉一致性的角色、地点、道具和建筑。清单自身、拍摄备注与未出镜的提及不算场景使用证据。
2. 核对并补齐场景引用路径，再按路径稳定去重。普通环境细节不必都单建资产；需稳定身份的关键物件不能漏列。有歧义查相关卡或提出问题。
3. 现有 script 清单中仍被使用的条目保留原新增/已有分类；Creator 建卡不会改变该资产在本集的来源分类。冲突分类先核实，不猜。
4. 首次登记的资产用 Glob 核对真实卡文件：存在则已有，否则新增。大纲提案只帮助识别，不能无条件并入；删去已放弃条目，但不删除共享资产文件。
5. 在 script 中更新清单，保存后运行 `node ${CLAUDE_PLUGIN_ROOT}/scripts/episode-assets.mjs story/episodes/{ep}/script.md all` 验证格式。人工逐场核对覆盖，解析器不负责判断出镜。

### 更新边界与采用已有剧本

script 已有清单时仅替换该二级段落及两子段，到下一 `## ` 标题前停止，保留用户拍摄备注等其他内容；缺清单则追加，不能把缺清单当重写剧本的理由。

采用提供的剧本时保留适用的场景、对白、结局与人物意图；只补必要的格式、路径、时长和清单。outline / novel / arc 均可不存在。历史 outline 清单不能替代场景核对，不迁移或回写其最终清单。

### 失败模式

1. 清单格式破损或误写在 outline —— script 清单消费者无法获得制作依据
2. asset id 英文化（违反 director-outline/rules.md「asset id 规则」）—— 与 creator-create-assets 文件名错配
3. 子段重复 / dedupe 不全（同 asset 在新增 + 复用同时出现）
4. 更新清单破坏其他二级段，或从清单自身反向推导“使用”导致已删资产永不退出
5. 建卡后将本集新增改成已有，或无条件保留未采用的大纲提案

## 公共失败模式 (须主动规避)

1. **写镜头建议** — 越权到分镜师领域 (如"全景推进"/"特写脸部"/"低角度仰拍")
2. **把剧本写成简化小说** — 无场景结构、无时长分配、无视觉摘要、无转场字段
3. **节奏分布失衡** — 剧情需要的转折或情绪变化缺少支撑，或重复场景挤掉关键表达；高潮比例仅作诊断参考，不按固定百分比或缺少高潮标签判失败
4. **场景对白配速不可拍** — 对白量与场景目标时长不匹配，后续切片必撞 speech-rate gate
5. **视觉摘要含具体镜头建议** — 应只描述视觉关键点 (构图、对比、符号道具)，不指定景别/镜头运动
6. **转场字段缺位** — 场景间缺"切/淡入淡出/叠化/划像"等转场指示
7. **清单不全 / 过度引入** — 剧本使用关键新道具却未列入 script 清单，或不必要的角色挤占有限时长使戏剧失焦

## 通用规则

- **台词精准** — 每句台词都必须为剧情推进或人物塑造服务，无废话
- **人物表达** — 按关系、欲望与隐瞒设计对白、独白、旁白或声音反应，保留有意义的动作和停顿，不为丰富而堆台词
- **场景具象化** — 场景描写必须具体、可视觉化，多用具象描写而非抽象叙述
- **节奏适配** — 严格遵循 config.md `每集时长目标`，重要场景留足铺垫空间，不在有限时长内压缩过多剧情
- **遵循已确认意图** — 有适用大纲时保留故事弧与结局；素材冲突或改编需要改变核心事件时提出方案交 Director 协调，不擅改其他 owner 的文件
- **角色声音一致** — 角色声音特征必须与资产文件中 `## 声音特征` 描述保持一致
- **内心与声音** — 在适合的场景积极运用内心独白与自言自语，展现人物的想法、感受和判断；结合上文的声音区别写出具体内容与表演，增强代入感。旁白、画外对话和字幕也可直接使用，不设“不可替代”门槛
- **注重画面感** — 多用具象描写而非抽象叙述；人物外貌、动作、表情有细节描写
- **权利与采用边界** — 现实人名、地名或商标出现本身不证明侵权；不静默改名或重设计合法提供材料。有具体权利疑虑、授权不清或角色级规则与保留要求冲突时，报告文本依据与影响，交 Director / 用户确认后再改受影响内容；不把改名当作合规保证
